Part 1 · Chapter 1

What is C#? — The Universal Craftsman

Before writing a single line of code, let's understand what C# actually is, where it came from, and why it has become one of the world's most powerful — and beloved — programming languages.

What you'll learn in this chapter

  • What C# is and the story of its creation
  • What the .NET runtime (CLR) is and why it matters
  • How C# runs on Windows, Mac, and Linux
  • The difference between C# (the language) and .NET (the platform)
  • Why C# is a great choice for backend development
  • Your very first C# program

The Universal Craftsman

Imagine a master craftsman who can work in any workshop, anywhere in the world. Whether the workshop is in Tokyo, Lagos, or New York — whatever tools are on the bench, whatever the local customs — this craftsman adapts instantly and produces beautiful work. The techniques in his head are universal. The workshop just needs to provide the right environment.

That is C# (pronounced "C sharp"). The code you write is the craftsman's technique — it doesn't change. The .NET runtime is the workshop environment that makes everything work on whatever machine you are running on.

🔨 The Craftsman Analogy

A carpenter's knowledge of joinery doesn't change whether they are in a workshop in London or Lagos. They need a local workbench (the operating system), local tools (the runtime), but their skill — their code — is the same everywhere.

C# code you write on your laptop will run identically on a Windows server, a Mac, or a Linux cloud container. The .NET runtime provides that consistent "workshop" in each environment. This is the promise: Write it once. Run it everywhere .NET is installed.

A Short History of C#

The story of C# begins in the late 1990s at Microsoft. The internet was booming, and Java — Sun Microsystems' cross-platform language — was becoming popular everywhere. Microsoft wanted a modern, powerful language of their own for the new .NET platform they were building.

They hired Anders Hejlsberg, a legendary Danish software engineer who had previously designed Turbo Pascal and later led the creation of Delphi — two hugely influential languages. Hejlsberg led a small team, and in 2000 they released C# 1.0 alongside the first version of the .NET Framework.

The language was designed from the start to be clean, strongly typed, object-oriented, and safe. Over the following two decades, C# evolved rapidly. By 2024, it is on version 12 and is considered one of the most feature-rich and thoughtfully designed languages in the world.

🎵 Fun Fact: The Name "COOL"

During internal development at Microsoft, the language was codenamed COOL — which stood for C-like Object Oriented Language. The name C# was chosen just before public release. In music, a sharp (#) means "raise the pitch by a half step." The team was signalling that C# was a step above C and C++ — a higher, cleaner version of the idea.

The .NET Runtime — C#'s Secret Engine

When you write C# and run it, your code doesn't speak directly to the computer's hardware. Something sits between your code and the machine. That something is the Common Language Runtime, or CLR.

Here is how it works: you write C# source code. A compiler translates it into an intermediate form called CIL (Common Intermediate Language) — sometimes also called MSIL. This CIL is stored in a .dll or .exe file. When you run the program, the CLR reads the CIL and compiles it further — using a JIT (Just-In-Time) compiler — into the native machine code for your specific CPU. This happens at runtime, and the CLR caches the result so it's fast.

Your C# Code (.cs files) ↓ C# Compiler (Roslyn) ↓ CIL / Bytecode (.dll or .exe) ← Same on every platform ↓ ┌──────────────┬──────────────┬──────────────┐ │ CLR │ CLR │ CLR │ │ (Windows) │ (macOS) │ (Linux) │ │ .NET 8 │ .NET 8 │ .NET 8 │ └──────────────┴──────────────┴──────────────┘

Beyond running your code, the CLR also provides:

  • Garbage Collection: automatically frees memory you are no longer using, so you don't have to manage it manually.
  • Type Safety: enforces that you only use objects in ways their type allows, catching bugs before they crash your program.
  • Exception Handling: provides a consistent system for errors across all .NET languages.
  • Security: enforces access controls on what your code can do.
📚 Key Term: CLR

The CLR (Common Language Runtime) is the execution engine of .NET. It takes the compiled intermediate code from your C# program and runs it on your specific machine. It also handles memory management, type safety, and exception handling automatically. Think of the CLR as the "engine room" that runs below every .NET application.

C# vs .NET — Language vs Platform

Beginners often mix up C# and .NET. They are related but different things:

  • C# is the programming language. It is the syntax and vocabulary you use to write your instructions. C# is one of several languages that compile to CIL and run on .NET — others include F# and Visual Basic.
  • .NET is the platform. It includes the CLR (runtime engine), the Base Class Library (thousands of pre-built classes for everything from file I/O to HTTP requests), and tooling like the dotnet CLI. .NET is the workshop; C# is the craftsman's skill.
💡 Which .NET Should You Use?

There have been multiple versions of .NET over the years, which can be confusing. Here is the short version: use .NET 8. It is the current Long-Term Support (LTS) release, meaning Microsoft will support it with security patches until November 2026. All examples in this book use .NET 8 and C# 12.

If you see references to ".NET Core" or ".NET Framework" online — don't panic. .NET Framework was the old Windows-only version. .NET Core (versions 1–3.1) was the cross-platform reboot. From .NET 5 onwards they unified into simply ".NET." Modern = .NET 8+.

Why C# for Backend Development?

C# and ASP.NET Core (the web framework we will cover in Parts 3 and 4) power the backends of companies like Stack Overflow, GoDaddy, Microsoft's own Azure services, and thousands of enterprise systems worldwide. Here is why developers choose C# for backend work:

  • Enterprise-grade reliability: C# has been battle-tested in demanding financial systems, healthcare software, and large-scale web services for over two decades.
  • Exceptional type safety: C# is a strongly, statically typed language. The compiler catches a huge category of bugs before your code even runs.
  • High performance: .NET 8 is one of the fastest web application runtimes in benchmarks like TechEmpower. It regularly outperforms Java and Node.js in raw throughput.
  • Modern language features: C# keeps gaining features — records, pattern matching, nullable reference types, async/await — that make code safer and more expressive.
  • Rich ecosystem: NuGet (the .NET package manager) hosts hundreds of thousands of libraries. Entity Framework Core, ASP.NET Core, SignalR — all world-class tools.
  • Jobs: C# is consistently in the top 10 most-used languages worldwide and is the dominant language in Microsoft-ecosystem enterprises and game development (Unity).

Your First C# Program

It is time to write some actual code. Every C# programmer has started with this. Let's look at two versions — the classic full form and the modern minimal form.

Classic form (explicit namespace and class):

using System;

namespace MyFirstApp
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello, World!");
        }
    }
}

Modern minimal form (C# 10+ / .NET 6+):

// Program.cs — the entire program!
Console.WriteLine("Hello, World!");

In modern .NET projects, the boilerplate class and Main method are generated for you implicitly, so you can start writing logic directly. Both versions output: Hello, World!

Let's understand the key parts of the classic form:

  • using System; — This imports the System namespace, which contains fundamental classes like Console. Without it, you would have to write System.Console.WriteLine every time.
  • namespace MyFirstApp — A namespace is like a folder for your code. It groups related classes together and prevents naming conflicts.
  • class Program — In C#, all code lives inside classes. Program is just a name — you could call it anything, but Program is the convention.
  • static void Main(string[] args) — This is the entry point of every C# application. When you run the program, the runtime looks for a method with exactly this signature. It's the front door of the building.
  • Console.WriteLine("Hello, World!") — Console is a class in the System namespace. WriteLine is a method that prints text followed by a newline character.
💡 Don't Panic About the Boilerplate

If static void Main(string[] args) looks overwhelming right now, that is perfectly normal. Every C# beginner has that moment. For now, treat it as the required opening spell to start your program. By Chapter 3, every word of it will make sense. The modern top-level statement style hides this behind the scenes, which is why new .NET projects use it by default.

A Taste of What C# Looks Like

Before we go deeper into all the concepts, here is a short taste of real C# code — a simple program that asks for your name and greets you: 

using System;

Console.Write("What is your name? ");
string name = Console.ReadLine() ?? "stranger";
Console.WriteLine($"Hello, {name}! Welcome to C#.");

// Output (if you type "Ada"):
// What is your name? Ada
// Hello, Ada! Welcome to C#.

A few things to notice:

  • string is the type for text. In C# types are lowercase keywords (string, int, bool) or PascalCase class names (Console).
  • $"Hello, {name}!" is an interpolated string — the $ prefix lets you embed variables directly inside the string with curly braces.
  • ?? is the null-coalescing operator — if ReadLine() returns null, use "stranger" instead. We will learn about null in Chapter 13.
📊 C# in the Real World

According to the 2024 Stack Overflow Developer Survey, C# is used by about 27% of professional developers, making it one of the top 5 most-used languages globally. Unity — the game engine powering thousands of games from Pokémon GO to Hollow Knight — uses C# as its scripting language. And ASP.NET Core regularly tops the TechEmpower performance benchmarks for web framework speed.

.NET Versions at a Glance

You will see many version numbers when looking up C# resources. Here is the map:

  • .NET Framework 1.0–4.8 — the original, Windows-only platform (2002–2019). Still exists for legacy systems.
  • .NET Core 1.0–3.1 — the cross-platform reboot (2016–2019). Fast, modern, but a separate product.
  • .NET 5 — unification of Core and Framework under one brand (2020).
  • .NET 6 — LTS release, added top-level statements, massive performance gains.
  • .NET 7 — current non-LTS, further performance and language improvements.
  • .NET 8 — LTS (use this!) — current recommended version as of 2024. Supported until November 2026.
📚 Key Terms

C#: A modern, strongly-typed, object-oriented programming language created by Anders Hejlsberg at Microsoft in 2000.

.NET: The platform (runtime + libraries + tooling) on which C# programs run. Cross-platform: Windows, macOS, Linux.

CLR (Common Language Runtime): The execution engine of .NET that runs your compiled C# code, manages memory, and provides type safety.

CIL (Common Intermediate Language): The "middle language" your C# code compiles to before the CLR translates it to native machine code.

JIT (Just-In-Time compiler): The component of the CLR that converts CIL to native CPU instructions at runtime.

NuGet: The package manager for .NET — the equivalent of npm (Node) or Maven (Java).

LTS (Long-Term Support): A version of .NET that Microsoft guarantees to support with security patches for at least 3 years.

Chapter Summary

  • C# was created by Anders Hejlsberg at Microsoft and released in 2000, originally codenamed "COOL."
  • C# code compiles to CIL (intermediate bytecode), which the CLR (Common Language Runtime) executes on any platform.
  • C# is the language; .NET is the platform. They work together but are distinct things.
  • .NET 8 is the current LTS version — it is what you should use for new projects in 2024.
  • The CLR provides automatic garbage collection, type safety, and cross-platform execution.
  • A C# program's entry point is the Main method, though modern .NET allows top-level statements that hide this boilerplate.
  • C# is used for enterprise backends, cloud services, game development (Unity), and much more.
