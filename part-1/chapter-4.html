Part 1 · Chapter 4

Inheritance — The Family Business

Why write the same code twice? Inheritance lets child classes absorb everything from their parent and add their own unique twist on top.

What you'll learn in this chapter

  • What inheritance is and why it reduces code duplication
  • The C# syntax for inheritance: the colon :
  • Base classes and derived classes
  • The protected access modifier — sharing with children
  • The base keyword — calling the parent constructor
  • Method overriding with virtual and override
  • sealed classes — stopping the inheritance chain

The Family Business

Imagine a family that has run a bakery for three generations. The grandfather established the business: he learned to bake, built relationships with suppliers, and created the customer service values. When his son took over, he didn't start from scratch — he inherited all those skills, the bakery itself, and the customer relationships. Then he added his own innovations: a café attached to the bakery, weekend cooking classes. His daughter inherited everything from both generations — and added online ordering.

Each generation inherited what came before and extended it with something new. That is exactly what inheritance does in C#.

🏪 The Family Business Analogy

A base class is the founding generation — it defines the core skills and properties shared by everyone in the family. Derived (child) classes inherit all of those, then add their own unique capabilities on top. You don't rewrite what already exists — you build on it.

Animal → Dog, Cat, Bird. All animals have a name and can eat. Dogs also bark. Cats also purr. Birds also fly.

Inheritance in C# — The Colon Syntax

In C#, inheritance is declared with a colon : after the class name, followed by the base class name. Let's build our Animal hierarchy: 

// Base class (also called parent class or superclass)
public class Animal
{
    public string Name { get; set; }
    public int Age { get; set; }

    public Animal(string name, int age)
    {
        Name = name;
        Age = age;
    }

    public void Eat()
    {
        Console.WriteLine($"{Name} is eating.");
    }

    public virtual void MakeSound()
    {
        Console.WriteLine($"{Name} makes a sound.");
    }

    public override string ToString() =>
        $"{Name} (age {Age})";
}

The key here is virtual on MakeSound(). This means "subclasses are allowed to override this method with their own version." Without virtual, the method is locked and cannot be overridden.

Derived Classes — Dog and Cat

Now let's create Dog and Cat, both inheriting from Animal: 

// Derived class (also called child class or subclass)
public class Dog : Animal
{
    public string Breed { get; set; }

    // Call the parent constructor with base(...)
    public Dog(string name, int age, string breed)
        : base(name, age)
    {
        Breed = breed;
    }

    // override — provide a Dog-specific implementation
    public override void MakeSound()
    {
        Console.WriteLine($"{Name} says: Woof! Woof!");
    }

    public void Fetch()
    {
        Console.WriteLine($"{Name} fetches the ball!");
    }
}

public class Cat : Animal
{
    public bool IsIndoor { get; set; }

    public Cat(string name, int age, bool isIndoor)
        : base(name, age)
    {
        IsIndoor = isIndoor;
    }

    public override void MakeSound()
    {
        Console.WriteLine($"{Name} says: Meow!");
    }

    public void Purr()
    {
        Console.WriteLine($"{Name} purrs contentedly...");
    }
}
💡 The base Keyword

When a derived class has a constructor, and the base class also requires parameters, you must call the base constructor using : base(...) after the derived constructor's parameter list. This runs the parent's constructor first — setting up all the inherited properties — before the child's constructor body runs.

Think of it as: "Before my setup ceremony, run my parent's setup ceremony first."

Using the Hierarchy

Let's see how a Dog and Cat object behave, inheriting from Animal: 

var dog = new Dog("Rex", 3, "German Shepherd");
var cat = new Cat("Whiskers", 5, true);

// Inherited from Animal
dog.Eat();         // Rex is eating.
cat.Eat();         // Whiskers is eating.

// Overridden — each provides its own version
dog.MakeSound();  // Rex says: Woof! Woof!
cat.MakeSound();  // Whiskers says: Meow!

// Dog-specific
dog.Fetch();       // Rex fetches the ball!

// Cat-specific
cat.Purr();        // Whiskers purrs contentedly...

// Inherited ToString()
Console.WriteLine(dog); // Rex (age 3)

What Does a Child Class Inherit?

A derived class inherits:

  • All public and protected properties and methods from the base class.
  • The ability to override any virtual methods.
  • Any methods it does not override — they work exactly as the parent defined them.

A derived class does not inherit:

  • private members — these are strictly internal to the base class.
  • Constructors — each class must define its own constructor (though it calls the parent's via base).

The protected Access Modifier

We saw private and public in Chapter 3. Now protected makes more sense in context: it means "only accessible within this class and in any class that inherits from it." 

public class Animal
{
    protected string _sound = "...";   // Children can access this

    public virtual void MakeSound()
    {
        Console.WriteLine($"{Name}: {_sound}");
    }
}

public class Dog : Animal
{
    public Dog(string name) : base(name, 0)
    {
        _sound = "Woof!";   // Accessible — _sound is protected
    }
}

Calling the Base Method

When you override a method, you can still call the parent's version using base.MethodName(). This is useful when you want to extend, not completely replace, the parent's behaviour: 

public class GuideDog : Dog
{
    public string Handler { get; set; }

    public GuideDog(string name, int age, string handler)
        : base(name, age, "Labrador")
    {
        Handler = handler;
    }

    public override void MakeSound()
    {
        base.MakeSound();  // First, do what Dog does (Woof!)
        Console.WriteLine($"{Name} is a guide dog for {Handler}.");
    }
}

var guide = new GuideDog("Buddy", 4, "James");
guide.MakeSound();
// Buddy says: Woof! Woof!
// Buddy is a guide dog for James.

Sealed Classes — No More Children

Sometimes you want to say: "This class can be used but cannot be further extended." The sealed keyword does exactly that: 

public sealed class Poodle : Dog
{
    public Poodle(string name, int age)
        : base(name, age, "Poodle") { }
}

// This would cause a compile error:
// public class MiniaturePoodle : Poodle { }  // Error: Poodle is sealed

Sealing a class is useful for security-critical classes, performance optimisations (the runtime can make certain assumptions about sealed classes), and design clarity — you are signalling "this is a final, complete implementation."

🔗 Single Inheritance in C#

C# (like Java) only allows single class inheritance — a class can only directly inherit from one base class. You cannot write class Dog : Animal, Pet. However, a class can implement multiple interfaces (which we will cover in Chapter 10). This limitation is deliberate — multiple inheritance of classes creates the "diamond problem," which causes confusing, hard-to-maintain code.

The Inheritance Chain Visualised

Animal / \ Dog Cat / \ GuideDog Poodle (sealed)

Every object in C# ultimately inherits from System.Object — the root of all types. That is where ToString(), Equals(), and GetHashCode() come from. You can override them in any class.

📚 Key Terms

Base class (parent / superclass): The class being inherited from. Defines shared properties and behaviour.

Derived class (child / subclass): A class that inherits from a base class using :.

Colon :: The C# syntax for declaring inheritance: class Dog : Animal.

base keyword: Used in a derived class to call the parent constructor (: base(...)) or the parent's method (base.Method()).

virtual: Marks a base class method as overridable by derived classes.

override: Marks a derived class method as replacing the parent's virtual method.

sealed: Prevents a class from being further inherited, or prevents a method from being further overridden.

protected: Accessible within the class and all derived classes, but not from unrelated code.

Chapter Summary

  • Inheritance lets derived classes reuse code from a base class without rewriting it.
  • In C#, inheritance uses the colon: class Dog : Animal.
  • The base keyword calls the parent constructor: : base(name, age).
  • Mark a method virtual in the base class to allow derived classes to override it.
  • Derived classes use override to replace a virtual method with a specific implementation.
  • protected members are accessible within the class and all its children.
  • sealed prevents a class (or method) from being further inherited/overridden.
  • C# supports only single class inheritance — a class can have exactly one base class.

{
    public virtual void Draw() => Console.WriteLine("Drawing a shape");

    public override void Draw() => Console.WriteLine("Drawing a circle");
