Part 0 · Chapter B

Data Structures — The Toolbox

Every tradesperson needs the right tool for the job. C# gives you a full toolbox of data structures — each one built for a different situation.

What you'll learn in this chapter

  • Arrays — the fixed-size, indexed container
  • List<T> — the flexible, resizable list
  • Dictionary<TKey, TValue> — lookup by key
  • Stack<T> — last in, first out (LIFO)
  • Queue<T> — first in, first out (FIFO)
  • HashSet<T> — unique values, no duplicates
  • When to choose which structure

The Tradesperson Analogy

A plumber, an electrician, and a carpenter all carry toolboxes — but the tools inside are completely different. A plumber doesn't reach for a saw when they need to tighten a pipe. They know which tool fits which job.

C# data structures are the same. Each one was designed for a specific kind of work. Using the right one means faster code, cleaner logic, and fewer bugs.

Arrays — The Fixed Grid

An array is the most basic data structure: a fixed-size, ordered collection of items of the same type. Think of it as a parking garage — it has a fixed number of spaces (set when you build it) and each space is numbered from 0. 

// Declare and initialise an array of 5 integers
int[] scores = new int[5];
scores[0] = 90;
scores[1] = 85;
scores[2] = 78;

// Initialise with values directly
string[] names = { "Alice", "Bob", "Carol" };

// Access elements by index (0-based)
Console.WriteLine(names[0]);   // "Alice"
Console.WriteLine(names.Length); // 3

// Loop through an array
foreach (string name in names)
{
    Console.WriteLine(name);
}

// 2D array
int[,] grid = new int[3, 3];
grid[0, 0] = 1;  // row 0, column 0
🅿️ The Parking Garage

When you build a parking garage, you decide upfront how many spaces it has — you cannot add more floors later. Each space has a number. An array works the same way: fixed size, numbered slots. Fast to access (just go straight to space #42), but you cannot grow it.

List<T> — The Resizable List

A List<T> is like an array that can grow. Under the hood it is an array, but when it runs out of space it automatically creates a larger one and copies everything over. You never have to think about the size. 

using System.Collections.Generic;

var fruits = new List<string>();

// Add items
fruits.Add("Apple");
fruits.Add("Banana");
fruits.Add("Cherry");

// Access by index
Console.WriteLine(fruits[1]);   // "Banana"

// Check and remove
Console.WriteLine(fruits.Contains("Apple"));  // true
fruits.Remove("Banana");
Console.WriteLine(fruits.Count);  // 2

// Initialise with values
var numbers = new List<int> { 10, 20, 30, 40 };

// Loop
foreach (var n in numbers)
    Console.WriteLine(n);
💡 List<T> is Your Everyday Default

When you need a collection of things and aren't sure which structure to use, start with List<T>. It handles most everyday needs: ordered, resizable, allows duplicates, indexed access. Only switch to a different structure when you have a specific reason.

Dictionary<TKey, TValue> — The Contact Book

A Dictionary stores key-value pairs. You look up a value by its key, just like looking up a phone number by a person's name. Every key must be unique. Lookups are extremely fast — essentially instant — regardless of how many entries you have. 

var capitals = new Dictionary<string, string>
{
    { "Nigeria",  "Abuja"     },
    { "Germany",  "Berlin"    },
    { "Japan",    "Tokyo"     }
};

// Look up by key
Console.WriteLine(capitals["Japan"]);  // "Tokyo"

// Check before accessing to avoid KeyNotFoundException
if (capitals.ContainsKey("France"))
    Console.WriteLine(capitals["France"]);

// Safer: TryGetValue
if (capitals.TryGetValue("Brazil", out string capital))
    Console.WriteLine(capital);

// Add and update
capitals["France"] = "Paris";   // adds if missing, updates if exists

// Iterate over all key-value pairs
foreach (var entry in capitals)
    Console.WriteLine($"{entry.Key} → {entry.Value}");
📒 The Contact Book

A phone book is a dictionary — you look up a name (key) and get a phone number (value). You would never scan every entry to find someone's number — you go straight to the name. C#'s Dictionary does exactly this: instant lookup by key, regardless of how many entries are stored.

Stack<T> — Last In, First Out

A Stack<T> is a collection where the last item you added is the first item you can remove. Think of a stack of plates — you can only take from the top. This is called LIFO (Last In, First Out). 

var history = new Stack<string>();

// Push adds to the top
history.Push("Page 1");
history.Push("Page 2");
history.Push("Page 3");

// Peek looks at the top without removing
Console.WriteLine(history.Peek());  // "Page 3"

// Pop removes from the top
Console.WriteLine(history.Pop());   // "Page 3"
Console.WriteLine(history.Pop());   // "Page 2"
Console.WriteLine(history.Count);  // 1
🍽️ The Plate Stack

In a cafeteria, clean plates are stacked. You always take from the top, and dirty plates are returned to the top. You can't grab the plate at the bottom without removing everything above it. A Stack<T> works identically. Common use case: undo history (most recent action undone first), call stacks, expression parsers.

Queue<T> — First In, First Out

A Queue<T> is the opposite of a Stack. The first item you add is the first item you remove — like a queue at a bank. This is called FIFO (First In, First Out). 

var printQueue = new Queue<string>();

// Enqueue adds to the back
printQueue.Enqueue("Document A");
printQueue.Enqueue("Document B");
printQueue.Enqueue("Document C");

// Dequeue removes from the front
Console.WriteLine(printQueue.Dequeue());  // "Document A"
Console.WriteLine(printQueue.Dequeue());  // "Document B"

// Peek looks at the front without removing
Console.WriteLine(printQueue.Peek());    // "Document C"

HashSet<T> — Unique Values Only

A HashSet<T> stores a collection of unique items. If you try to add something that already exists, it is silently ignored. Lookups are as fast as a Dictionary. There is no ordering or indexing — it just tells you whether something is in the set or not. 

var visitors = new HashSet<string>();

visitors.Add("Alice");
visitors.Add("Bob");
visitors.Add("Alice");   // duplicate — silently ignored
Console.WriteLine(visitors.Count);  // 2 — Alice counted once

// Fast membership check
Console.WriteLine(visitors.Contains("Bob"));   // true
Console.WriteLine(visitors.Contains("Carol")); // false

// Set operations
var admins = new HashSet<string> { "Alice", "David" };
visitors.IntersectWith(admins);   // visitors who are also admins
Console.WriteLine(visitors.Count); // 1 — only "Alice"

When to Choose Which Structure

Structure Ordered? Duplicates? Best for
int[] / array Yes Yes Fixed-size collections, performance-critical loops
List<T> Yes Yes Most everyday needs — ordered, resizable, general-purpose
Dictionary<K,V> No Keys: No Fast key-based lookup (user IDs, settings, caches)
Stack<T> LIFO Yes Undo history, call tracking, expression parsing
Queue<T> FIFO Yes Task queues, print queues, message buffers
HashSet<T> No No Fast membership tests, deduplication, set operations
🔍 What About LinkedList?

C# also has LinkedList<T> — a doubly linked list where each node points to the previous and next. It is great when you need to insert or remove items in the middle frequently (O(1) insertion after a known node). However, it lacks random access (no list[5]) and is rarely needed in everyday web API work. You'll know when you need it.

Chapter Summary

  • Arrays are fixed-size and fast; use when size is known upfront.
  • List<T> is your general-purpose, resizable ordered collection.
  • Dictionary<TKey, TValue> provides near-instant lookup by key — ideal for caches and settings.
  • Stack<T> is LIFO — the last item in is the first out. Use for undo, history, recursion simulation.
  • Queue<T> is FIFO — the first item in is the first out. Use for task and message processing.
  • HashSet<T> stores only unique items and provides fast membership checks.
