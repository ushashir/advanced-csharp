Part 0 · Chapter A

C# Data Types — The Containers

Before objects, classes, or APIs — everything in C# is data. This chapter covers every type of container C# gives you to store that data.

What you'll learn in this chapter

  • The difference between value types and reference types
  • Every built-in numeric type: int, long, double, float, decimal
  • Text and character types: string and char
  • Boolean and byte types
  • The var keyword and type inference
  • Type conversion: implicit, explicit, and Convert
  • Default values and constants

The Kitchen Cupboard Analogy

Think of your kitchen. You don't store cooking oil in a sugar jar or put flour in a bottle. Every ingredient has a specific container shaped for it. You'd never try to pour soup into a pepper shaker.

Data types in C# work the same way. Every piece of data has a type — a specific kind of container — and C# enforces that you use the right container for the right data. This makes your programs safer and faster.

🏠 The Storage Room

Imagine a storage room with labelled boxes. Each box has a size and a purpose — a small box for coins (byte), a medium box for whole numbers (int), a big box for huge numbers (long), a bottle for precise measurements (decimal), a notepad for text (string). C# won't let you put a paragraph of text into a coin box — it would be wrong and it would break.

Value Types vs Reference Types

This is the most important distinction in C# data types. All types fall into one of two categories:

Value Types

A value type stores the data itself directly in memory. When you copy a value type, you get a completely independent copy. Changes to the copy do not affect the original. 

int a = 10;
int b = a;   // b gets its own copy of 10
b = 20;
Console.WriteLine(a);  // 10 — unchanged
Console.WriteLine(b);  // 20

Value types include: int, long, double, float, decimal, bool, char, byte, short, and all structs.

Reference Types

A reference type stores a pointer (address) to where the data lives in memory. When you copy a reference type, both variables point to the same data. Changing one changes the other. 

string[] names1 = { "Alice", "Bob" };
string[] names2 = names1;   // both point to the SAME array
names2[0] = "Charlie";
Console.WriteLine(names1[0]);  // "Charlie" — names1 changed too!

Reference types include: string, arrays, classes, interfaces, and delegates.

📚 Key Term: Stack vs Heap

Value types live on the stack — a fast, short-lived block of memory. Reference types live on the heap — a larger, longer-lived area managed by the garbage collector. You don't need to manage this manually in C# — the CLR handles it — but knowing the difference helps you understand performance and copying behaviour.

Integer Types

C# gives you several integer types depending on how large your numbers need to be:

TypeSizeRangeWhen to use
byte8 bits0 to 255Small positive numbers (image pixels, flags)
short16 bits−32,768 to 32,767Rarely used directly
int32 bits−2.1B to 2.1BYour everyday integer. Use this by default.
long64 bits−9.2 quintillion to 9.2 quintillionLarge IDs, timestamps, file sizes
byte age = 25;
int population = 8_000_000_000;   // underscores for readability
long distanceToStar = 9_461_000_000_000L;  // 'L' suffix for long literal
💡 Default to int

Unless you have a specific reason (very large numbers → long, memory-sensitive work → byte), always use int for whole numbers. It matches the CPU's natural register size on most machines and is what C# expects in most contexts.

Floating-Point Types

For numbers with decimal points, C# provides three options:

TypePrecisionSuffixWhen to use
float~7 digitsfGraphics, games — speed over precision
double~15 digits(none)Scientific, general-purpose decimals
decimal~28 digitsmMoney, finance — never use float/double for currency
float speed = 29.5f;           // 'f' required for float literals
double gravity = 9.80665;       // default for decimal literals
decimal price = 19.99m;         // 'm' required for decimal literals
⚠️ Never Use float or double for Money

Try this: Console.WriteLine(0.1 + 0.2); You get 0.30000000000000004. This is because computers store decimals in binary, and some fractions cannot be represented exactly. For financial calculations, always use decimal — it avoids these rounding errors.

The bool Type

A bool (boolean) holds exactly one of two values: true or false. It is used for conditions, flags, and logical operations. 

bool isLoggedIn = true;
bool hasPermission = false;

// Comparisons always return a bool
bool isAdult = age >= 18;    // true if age is 18 or more
bool isEmpty = name == "";   // true if name is empty

// Logical operators
bool canEnter = isLoggedIn && hasPermission;   // AND
bool canView  = isLoggedIn || isGuest;         // OR
bool isBlocked = !isLoggedIn;                  // NOT

The char Type

A char holds a single character. It uses single quotes, not double quotes. Under the hood, a char is a 16-bit Unicode code point. 

char grade = 'A';
char symbol = '£';
char newline = '\n';   // escape sequences work in char

// char can be compared numerically
Console.WriteLine('A' < 'Z');  // true — 'A' is 65, 'Z' is 90

The string Type

A string is a sequence of characters. It is a reference type but it behaves like a value type because strings in C# are immutable — once created, a string cannot be changed. Every "modification" creates a new string. 

string name = "Ushahemba";
string city = "Lagos";

// String interpolation — embed variables with $
string greeting = $"Hello, {name}! You are from {city}.";

// Useful string methods
Console.WriteLine(name.ToUpper());       // "USHAHEMBA"
Console.WriteLine(name.Length);          // 9
Console.WriteLine(name.Contains("ha"));  // true
Console.WriteLine(name.Replace("a", "@")); // "Ush@hemb@"
Console.WriteLine(name[0]);               // 'U' — indexing gives a char
🎯 String Immutability

When you do name = name + " Shir", C# does not modify the original string. It creates a brand new string "Ushahemba Shir" and points name to it. The old "Ushahemba" string is abandoned and eventually cleaned up by the garbage collector. This is why for heavy string building (thousands of concatenations), you should use StringBuilder instead.

The var Keyword — Type Inference

C# can often infer the type of a variable from the value you assign to it. The var keyword tells the compiler: "Figure out the type yourself." 

var count = 42;          // compiler infers: int
var name = "Ushahemba";  // compiler infers: string
var price = 9.99m;       // compiler infers: decimal
var isReady = true;       // compiler infers: bool
💡 var is not dynamic

var is still statically typed — the type is fixed at compile time, the compiler just works it out for you. You cannot later assign a string to a variable declared as var count = 42. Once inferred as int, it stays int. Use var when the type is obvious from the assignment; use explicit types when clarity matters.

Type Conversion

Sometimes you need to convert data from one type to another. C# gives you three ways:

Implicit Conversion (Automatic)

C# converts automatically when there is no risk of data loss (small → large).

int age = 25;
long bigAge = age;      // int fits inside long — automatic
double d = age;         // int fits inside double — automatic

Explicit Conversion (Casting)

When there is risk of data loss, you must cast explicitly using (type).

double pi = 3.14159;
int truncated = (int) pi;    // 3 — decimal part is lost

long bigNum = 1_000_000_000_000L;
int overflow = (int) bigNum;  // data loss — value wraps around!

Using Convert and Parse

For conversions involving strings (user input, files, APIs), use Convert or Parse.

string input = "42";

// Parse — throws an exception if the string is not a valid number
int number = int.Parse(input);

// TryParse — returns false instead of throwing
if (int.TryParse(input, out int result))
{
    Console.WriteLine($"Parsed: {result}");
}

// Convert — handles null gracefully (returns 0 instead of throwing)
int safe = Convert.ToInt32(input);
💡 Always Prefer TryParse

When parsing user input, always use TryParse instead of Parse. Users type unexpected things. Parse will throw an exception and crash your program if the input is invalid. TryParse lets you handle the failure gracefully.

Constants and readonly

Sometimes a value should never change. C# gives you two ways to lock a value: 

// const — compile-time constant, must be a literal value
const double Pi = 3.14159265358979;
const int MaxRetries = 3;
const string AppName = "My API";

// readonly — set once (in constructor or inline), then immutable
readonly string ServerId = Guid.NewGuid().ToString();
📚 const vs readonly

Use const for values that are truly fixed forever — mathematical constants, limits, names that will never change. Use readonly when the value is set at runtime (e.g., from configuration or generated once in a constructor) but should never change after that.

Chapter Summary

  • Value types store data directly; reference types store a pointer to data in the heap.
  • For integers, default to int. Use long for large numbers.
  • For decimals, use double for general use and decimal for money.
  • A string is a reference type but behaves like a value type — it is immutable.
  • var uses type inference at compile time — the type is still strongly fixed.
  • Use explicit casting (type) when converting between types with potential data loss.
  • Always use TryParse when parsing user-provided strings.
  • const locks a compile-time value; readonly locks a runtime value.
