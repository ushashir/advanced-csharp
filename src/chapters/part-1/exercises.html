Part 1 Exercises — Object-Oriented Programming

These exercises consolidate everything from Part 1 — classes, objects, encapsulation, inheritance, polymorphism, and abstraction. Work through them in order; each one builds on the last. Some ask you to think and write prose; others ask you to write code. All of them make you a stronger C# programmer.

What these exercises cover

  • Classes, objects, constructors, and properties (Chapters 1–2)
  • Encapsulation and access modifiers (Chapter 3)
  • Inheritance, base classes, and the base keyword (Chapter 4)
  • Polymorphism, virtual, override, and method hiding (Chapter 5)
  • Abstraction, abstract classes, and interfaces (Chapter 6)
  • The sealed keyword and when to use it

Exercises

Exercise P1.1 — Reflection: What Is an Object?

In your own words — without using any code — explain the difference between a class and an object. Use a real-world analogy that is different from the ones used in the book. For example, you might think about a recipe versus a baked cake, or a blueprint versus a house, or a species versus an individual animal. Describe: what the class represents, what each object (instance) represents, and how multiple objects can exist from the same class.

Write at least four sentences. This is a thinking exercise — there is no single right answer.

Exercise P1.2 — Code Challenge: Build a BankAccount Class

Create a BankAccount class that models a simple bank account. Your class must:

  • Have a private field _balance of type decimal
  • Have a public read-only property Balance (getter only — no external code should be able to set the balance directly)
  • Have a public property Owner of type string
  • Have a constructor that takes an owner name and an optional opening balance (default 0)
  • Have a Deposit(decimal amount) method that adds money (throw an exception if amount is negative)
  • Have a Withdraw(decimal amount) method that subtracts money (throw an exception if the withdrawal would put the balance below zero)
  • Override ToString() to return "Account[Owner] Balance: £X.XX"

Write a short Main program that creates two accounts, deposits and withdraws from each, and prints the results.

Example expected output (values are illustrative):

// Expected output:
// Account[Alice] Balance: £500.00
// Account[Bob] Balance: £1200.00
Exercise P1.3 — Code Challenge: Inheritance Hierarchy

Design an inheritance hierarchy for a simple vehicle management system. Start with a base class Vehicle and extend it:

  • Vehicle — properties: Make, Model, Year; method: virtual string Describe()
  • Car : Vehicle — adds NumberOfDoors; overrides Describe() to include doors
  • Truck : Vehicle — adds PayloadTonnes; overrides Describe() to include payload
  • ElectricCar : Car — adds RangeKm; overrides Describe() to include range

Each override should call base.Describe() and append the new information, so the description builds up through the hierarchy. Create one instance of each type and print all four descriptions.

Exercise P1.4 — Interactive Quiz: The sealed Keyword

What keyword in C# prevents a class from being inherited by any subclass?

Exercise P1.5 — Code Challenge: Polymorphism in Practice

Create an abstract base class Shape with an abstract method double Area() and a concrete method void PrintArea() that calls Area() and prints the result.

Implement three concrete shapes:

  • Circle — takes a radius; Area = π × r²
  • Rectangle — takes width and height; Area = width × height
  • Triangle — takes base and height; Area = 0.5 × base × height

Then create a List<Shape> containing one of each shape. Loop through the list and call PrintArea() on each one. Notice how polymorphism lets you treat all shapes the same way through the base class reference. 

// Expected output (values approximate):
// Circle area: 78.54
// Rectangle area: 24.00
// Triangle area: 10.00
Exercise P1.6 — Reflection: Encapsulation

Consider this poorly-written class: 

public class Person
{
    public string Name;
    public int Age;
    public string PasswordHash;
    public decimal Salary;
}

All fields are public. List at least three specific problems this causes. For each problem, describe how you would fix it using proper encapsulation (private fields, public properties with getters/setters, validation logic, or access modifiers). Think about who should be allowed to read and write each piece of data, and what validation might be needed (for example, can an age be negative?).

Exercise P1.7 — Code Challenge: Interface Contract

Define an interface IAnimal with the following members:

  • string Name { get; }
  • string Sound { get; }
  • void Speak() — prints "[Name] says [Sound]!"

Implement IAnimal in three classes: Dog, Cat, and Parrot. Each class must provide its own Name and Sound. The Parrot class should also add a method Mimic(string phrase) that prints "Parrot repeats: [phrase]".

Create an array of type IAnimal[] containing all three animals. Loop through it and call Speak() on each. Then cast the last element to Parrot and call Mimic("Hello there!").

Exercise P1.8 — Bring It All Together: Library System

This is your capstone exercise for Part 1. Design a small library management system using every OOP concept from this part. Requirements:

  • Abstract base class LibraryItem — properties: Title, ItemId, IsCheckedOut (bool); abstract method string GetInfo(); concrete methods CheckOut() and Return().
  • Book : LibraryItem — adds Author and Pages; overrides GetInfo().
  • DVD : LibraryItem — adds Director and DurationMinutes; overrides GetInfo().
  • Interface IReservable — method Reserve(string memberName); property ReservedBy. Implement this on Book only.
  • Library class — holds a List<LibraryItem>; methods: AddItem(LibraryItem), PrintCatalogue(), CheckOutItem(string itemId).

Write a Main program that creates a Library, adds 3 books and 2 DVDs, checks out two items, reserves one book, and prints the full catalogue showing each item's status.

💡 Tip

This exercise is intentionally open-ended. There is no single correct implementation. Focus on using the right OOP tool for each requirement: use abstract when you want to force subclasses to implement something, use an interface when you want to add optional capability, and use encapsulation to protect state from being set to invalid values.

Part 1 Complete — What You Have Mastered

  • Classes are blueprints; objects are living instances with their own state.
  • Encapsulation hides internal state behind a controlled interface using access modifiers and properties.
  • Inheritance lets child classes reuse and extend parent class behaviour using : syntax.
  • Polymorphism lets you treat different types uniformly through a shared base type, with virtual and override methods dispatching to the correct implementation at runtime.
  • Abstract classes define a partial contract; interfaces define a pure capability contract.
  • The sealed keyword locks down a class or method from further extension.

You are now ready for Part 2 — Advanced C# Concepts. The OOP foundation you have just built is what every advanced feature in Part 2 is built on top of.
