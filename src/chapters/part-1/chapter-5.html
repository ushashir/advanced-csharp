Part 1 · Chapter 5

Polymorphism — One Name, Many Forms

The same method call. Dozens of different behaviours. Polymorphism is what makes object-oriented code elegant, flexible, and genuinely powerful.

What you'll learn in this chapter

  • What polymorphism means (runtime vs compile-time)
  • Runtime polymorphism: virtual/override called through a base reference
  • Compile-time polymorphism: method overloading
  • Using a list of base-type objects and calling methods polymorphically
  • The is keyword for type checking
  • The as keyword for safe casting
  • Upcasting and downcasting explained simply

The Play Button

Think about the "play" button. Every device that can play media has one. Your phone has a play button. Your laptop has a play button. Your TV remote has a play button. Your car stereo has a play button. Same symbol. Same concept. But press play on a phone and music streams from Spotify. Press it on a TV and Netflix starts. Press it on a car stereo and your USB stick begins playing.

One button name. Different behaviour depending on what device you are using. That is polymorphism.

▶️ The Play Button Analogy

In code, polymorphism means you call the same method — say MakeSound() — on a collection of objects. Each object responds in its own way, even though you are calling the same method name through the same base-type reference.

You don't need to write an if check for every type. You just call the method, and the right version runs automatically. The runtime figures it out.

Two Kinds of Polymorphism

C# has two forms of polymorphism:

  • Runtime polymorphism (also called dynamic dispatch or method overriding): the specific method that runs is determined at runtime, based on the actual type of the object. This is what virtual/override gives you.
  • Compile-time polymorphism (also called method overloading): you have multiple methods with the same name but different parameter lists. The compiler chooses which one to call at compile time, based on the arguments you provide.

Runtime Polymorphism — The Power of Virtual

We built our Animal hierarchy in Chapter 4. Now let's see how polymorphism makes it genuinely powerful. We can store any animal in an Animal reference and call MakeSound() — the right version runs automatically: 

using System.Collections.Generic;

// All animals stored as the base type: Animal
var animals = new List<Animal>
{
    new Dog("Rex", 3, "German Shepherd"),
    new Cat("Whiskers", 5, true),
    new Dog("Buddy", 2, "Labrador"),
    new Cat("Luna", 1, false),
};

// One loop. One method call. Four different responses.
foreach (Animal animal in animals)
{
    animal.MakeSound();
}

// Output:
// Rex says: Woof! Woof!
// Whiskers says: Meow!
// Buddy says: Woof! Woof!
// Luna says: Meow!

Notice: we declared each loop variable as Animal, but the actual object is a Dog or Cat. When we call MakeSound(), C# looks at the actual runtime type of the object — not the declared type of the variable — and calls the correct override. This is the essence of runtime polymorphism.

💡 Without Polymorphism — What It Would Look Like

Without polymorphism, you would need to check the type of every object yourself: 

// Ugly, fragile, does NOT scale
foreach (var animal in animals)
{
    if (animal is Dog d) d.MakeSound();
    else if (animal is Cat c) c.MakeSound();
    // ... add a new Animal type → must update this code!
}

Polymorphism eliminates this. Add a Bird class, override MakeSound(), and the loop just works — no changes needed anywhere.

Compile-Time Polymorphism — Method Overloading

Method overloading means defining multiple methods with the same name but different parameter signatures. The compiler picks the right one at compile time based on what arguments you pass: 

public class Calculator
{
    // Add two integers
    public int Add(int a, int b) => a + b;

    // Add two doubles
    public double Add(double a, double b) => a + b;

    // Add three integers
    public int Add(int a, int b, int c) => a + b + c;

    // Concatenate strings
    public string Add(string a, string b) => a + b;
}

var calc = new Calculator();
Console.WriteLine(calc.Add(2, 3));           // 5 (int overload)
Console.WriteLine(calc.Add(2.5, 3.1));       // 5.6 (double overload)
Console.WriteLine(calc.Add(1, 2, 3));        // 6 (three-param overload)
Console.WriteLine(calc.Add("Hello, ", "World!")); // Hello, World!

The C# compiler looks at the types of the arguments you provide and selects the matching overload automatically. You call Add — the right version runs. Same name, many forms.

Upcasting — Treating a Child as a Parent

When we stored Dog and Cat objects in a List<Animal>, that was upcasting. You are treating a more specific type as its more general parent type. This always works and is always safe — a Dog IS-AN Animal, so it can always be used as an Animal. 

Dog myDog = new Dog("Rex", 3, "German Shepherd");

// Upcast — always safe, no cast needed
Animal animal = myDog;

animal.MakeSound(); // Rex says: Woof! Woof! — still calls Dog's version!
animal.Eat();       // Rex is eating. — inherited from Animal

// animal.Fetch(); — COMPILE ERROR! Animal type doesn't know about Fetch()

After upcasting, you can only call methods and properties that exist on Animal (the declared type). But the runtime behaviour is still the Dog's overridden version.

Downcasting — Getting Back to the Specific Type

If you have a base-type reference and you know (or need to check) what the actual type is, you can downcast — cast it back to the specific type: 

Animal animal = new Dog("Rex", 3, "Shepherd");

// Direct cast — will throw InvalidCastException if wrong type
Dog dog = (Dog)animal;
dog.Fetch(); // Rex fetches the ball!

Direct casting is risky — if animal is actually a Cat, this throws a runtime exception. Use the is and as keywords for safer approaches.

The is Keyword — Type Checking

The is keyword checks whether an object is of a specific type. Modern C# (version 7+) combines the check and the cast into one clean line using pattern matching: 

foreach (Animal animal in animals)
{
    // Pattern matching — checks type AND creates a typed variable in one step
    if (animal is Dog dog)
    {
        Console.WriteLine($"{dog.Name} is a {dog.Breed}");
        dog.Fetch(); // Safe! We know it's a Dog here
    }
    else if (animal is Cat cat)
    {
        Console.WriteLine($"{cat.Name} is indoor: {cat.IsIndoor}");
        cat.Purr();
    }
}

The is Dog dog syntax checks if animal is a Dog, and if so, assigns it to the variable dog — all in one expression. This is far cleaner and safer than a separate cast.

The as Keyword — Safe Casting

The as keyword attempts a cast and returns null if it fails (instead of throwing an exception): 

Animal animal = GetSomeAnimal();  // could be Dog or Cat

Dog dog = animal as Dog;

if (dog != null)
{
    dog.Fetch(); // Safe to use
}
else
{
    Console.WriteLine("Not a dog, skipping fetch.");
}
💡 Prefer is Pattern Matching in Modern C#

In modern C# (7+), the is pattern matching syntax is preferred over as followed by a null check. It is cleaner and less error-prone. Use: if (animal is Dog dog) rather than var dog = animal as Dog; if (dog != null).

Switch Expressions with Pattern Matching (C# 8+)

C# 8 introduced a very elegant way to handle polymorphic type switching using switch expressions with type patterns: 

string Describe(Animal animal) => animal switch
{
    Dog d => $"{d.Name} is a {d.Breed} dog",
    Cat c => $"{c.Name} is a {(c.IsIndoor ? "indoor" : "outdoor")} cat",
    _ => $"{animal.Name} is some kind of animal"
};

foreach (var a in animals)
    Console.WriteLine(Describe(a));

The _ is a discard pattern — it matches anything that didn't match the patterns above it. This style is beautifully concise and very idiomatic in modern C#.

🌟 The Open/Closed Principle

Polymorphism is the engine behind one of the most important design principles in software engineering: the Open/Closed Principle (the "O" in SOLID). It says: "software entities should be open for extension, but closed for modification."

With polymorphism, you can add a new Bird class that overrides MakeSound(), and every existing loop and method that works with Animal objects will automatically handle Bird correctly — without changing a single line of existing code. Open for new types. Closed to breaking changes.

📚 Key Terms

Polymorphism: The ability for one interface (method name/signature) to have different implementations depending on the object type.

Runtime polymorphism: The specific method to run is determined at runtime based on the object's actual type. Enabled by virtual/override.

Compile-time polymorphism (overloading): Multiple methods with the same name but different parameter lists. Resolved at compile time.

Upcasting: Treating a derived type as its base type. Always safe and implicit.

Downcasting: Casting a base-type reference back to a specific derived type. Can fail — use is or as.

is keyword: Tests if an object is of a type. With pattern matching: also creates a typed variable in one step.

as keyword: Attempts a cast; returns null if the cast fails (does not throw).

Chapter Summary

  • Polymorphism means "one name, many forms" — the same method call behaves differently depending on the object.
  • Runtime polymorphism uses virtual/override. The CLR determines at runtime which override to call.
  • Compile-time polymorphism is method overloading — same name, different parameter lists, resolved by the compiler.
  • Objects can be stored as their base type (upcasting) — the overridden methods still run correctly.
  • Use is with pattern matching to safely check and cast types in one step.
  • as returns null instead of throwing an exception if the cast fails.
  • Polymorphism is the key to writing code that is open for extension without breaking existing logic.
