Classes and Objects — The Blueprint and the Building

The class is the architectural plan. The object is the actual building you can walk into. Everything in C# is built from this single idea.

What you'll learn in this chapter

  • What a class is (the blueprint analogy)
  • What an object is and how to create one with new
  • Fields vs Properties — and why C# prefers properties
  • Auto-implemented properties with { get; set; }
  • Constructors — setting up an object from birth
  • A complete, real-world Car class with multiple instances

The Blueprint and the Building

Imagine an architect who designs a house. She draws up a detailed blueprint: three bedrooms, two bathrooms, a kitchen with an island, a garage for two cars. The blueprint is just paper — you cannot live in a blueprint. But give that blueprint to a builder, and they can construct an actual house. Give it to another builder, and they build another house. And another. Each house is its own physical building — you can paint them different colours, furnish them differently, live different lives in them. But they all came from the same plan.

In C#:

  • The blueprint is the class.
  • Each house built from that blueprint is an object (also called an instance).
🏗️ The Blueprint Analogy

An architect's blueprint defines everything a house will have: the number of rooms, the position of windows, the layout of pipes. But the blueprint itself is not a house — no one sleeps in a blueprint.

A class defines what properties an object will have (like Make, Model, Year) and what it can do (like Describe()). An object is a real, live instance of that class — an actual car with specific values for those properties, living in memory, ready to be used.

Defining a Class

Let's define a Car class. Every car has a make (brand), a model name, and a year. Every car can also describe itself. Here is the skeleton: 

public class Car
{
    // Fields — raw storage variables (usually private)
    private string _make;
    private string _model;
    private int _year;
}

This class describes a car, but it is empty of useful functionality yet. In C# we rarely expose raw fields directly. Instead, we use properties.

Fields vs Properties

In Java, it is common to create private fields and then write explicit getXxx() and setXxx() methods. C# has a cleaner built-in syntax for this called properties.

A property looks like a field from the outside but behaves like a method — it can include validation logic inside its get and set accessors. 

public class Car
{
    // Auto-implemented property — C# creates a hidden backing field automatically
    public string Make { get; set; }
    public string Model { get; set; }
    public int Year { get; set; }
}

The { get; set; } syntax is called an auto-implemented property. C# automatically creates the hidden backing field for you. This is the idiomatic C# way — you will see it everywhere.

💡 Naming Convention

In C#, properties use PascalCase (every word capitalised): Make, Model, Year. Private fields use camelCase with an underscore prefix: _make, _model. Local variables and method parameters use plain camelCase: make, carMake. This is the official Microsoft C# style guide convention.

Constructors — Setting Up from Birth

Right now, if you create a Car object, all its properties will have default values: null for strings, 0 for integers. That is not very useful. We want to be able to create a car with all its details at once.

A constructor is a special method that runs automatically when you create an object. It has the same name as the class and no return type. Think of it as the setup ceremony: the moment an object comes into existence, the constructor runs and gets everything ready. 

public class Car
{
    public string Make { get; set; }
    public string Model { get; set; }
    public int Year { get; set; }

    // Constructor — same name as class, no return type
    public Car(string make, string model, int year)
    {
        Make = make;
        Model = model;
        Year = year;
    }

    // Method — what the car can do
    public void Describe()
    {
        Console.WriteLine($"{Year} {Make} {Model}");
    }
}
💡 C# vs Java: No this. Required

In Java constructors, you often write this.make = make because the field and parameter have the same name. In C# with properties, the parameter names typically differ from the property names (lowercase vs PascalCase), so there is no ambiguity. You can write simply Make = make; without this.. (You can use this.Make in C# — it just is not required here.)

Creating Objects with new

To create an object from a class, use the new keyword. Think of new as instructing the runtime: "Build me one of these, using this blueprint, and set it up with these initial values." 

// Create Car objects
Car car1 = new Car("Toyota", "Camry", 2022);
Car car2 = new Car("Honda", "Civic", 2019);
Car car3 = new Car("Ford", "Mustang", 2023);

car1.Describe(); // 2022 Toyota Camry
car2.Describe(); // 2019 Honda Civic
car3.Describe(); // 2023 Ford Mustang

Three different objects. Each one is independent — changing car1.Make has absolutely no effect on car2 or car3. They share the same blueprint but they are completely separate instances in memory.

C# 9+ Target-Typed new

In modern C# (version 9 and later), if the type is already known from context, you can drop the type name after new: 

// Traditional
Car car1 = new Car("Toyota", "Camry", 2022);

// Modern target-typed new (C# 9+)
Car car1 = new("Toyota", "Camry", 2022);

// Or with var (the compiler infers the type)
var car1 = new Car("Toyota", "Camry", 2022);

All three lines do the exact same thing. The var keyword tells the compiler "figure out the type from the right-hand side." You will see var used heavily in modern C# to reduce verbosity.

Object Initialiser Syntax

C# has another clean shortcut: the object initialiser. When a class has a parameterless constructor (or no custom constructor at all), you can set properties directly in curly braces: 

public class Car
{
    public string Make { get; set; }
    public string Model { get; set; }
    public int Year { get; set; }

    public void Describe() =>
        Console.WriteLine($"{Year} {Make} {Model}");
}

// Object initialiser — no constructor needed
var car = new Car
{
    Make = "BMW",
    Model = "3 Series",
    Year = 2021
};

car.Describe(); // 2021 BMW 3 Series

You can also notice public void Describe() => ... — this is an expression-bodied method, C# shorthand for single-line methods. The => (arrow) replaces the curly braces and return keyword.

The Full Car Class — Putting It Together

Let's write a complete, realistic Car class that combines constructors, properties, methods, and multiple instances: 

using System;
using System.Collections.Generic;

public class Car
{
    // Auto-implemented properties
    public string Make { get; set; }
    public string Model { get; set; }
    public int Year { get; set; }
    public double PriceGbp { get; set; }

    // Constructor
    public Car(string make, string model, int year, double priceGbp)
    {
        Make = make;
        Model = model;
        Year = year;
        PriceGbp = priceGbp;
    }

    // Describe the car
    public void Describe()
    {
        Console.WriteLine($"{Year} {Make} {Model} — £{PriceGbp:N0}");
    }

    // A computed property — derived from other properties
    public int Age => 2024 - Year;
}

// Usage
var cars = new List<Car>
{
    new Car("Toyota", "Camry", 2022, 28000),
    new Car("Honda", "Civic", 2019, 15000),
    new Car("Ford", "Mustang", 2023, 42000),
};

foreach (var car in cars)
{
    car.Describe();
    Console.WriteLine($"  → Age: {car.Age} year(s)");
}

Output:

2022 Toyota Camry — £28,000
  → Age: 2 year(s)
2019 Honda Civic — £15,000
  → Age: 5 year(s)
2023 Ford Mustang — £42,000
  → Age: 1 year(s)
💡 Computed Properties

Notice the Age property: public int Age => 2024 - Year; This is a computed (read-only) property. It has no setter — you can only read it. Every time you access car.Age, it calculates the value on the fly. This is a very clean C# pattern — no need for a separate GetAge() method like in Java.

The Class vs Instance Distinction

One last concept to nail down: the difference between what belongs to the class versus what belongs to each instance.

  • Instance members (no static keyword) belong to each individual object. car1.Make and car2.Make can be different values — they are stored separately per object.
  • Static members (static keyword) belong to the class itself, not any single object. There is only one copy, shared by everyone. For example, a static counter that tracks how many cars have been created: 
public class Car
{
    public static int TotalCreated { get; private set; } = 0;

    public string Make { get; set; }

    public Car(string make)
    {
        Make = make;
        Car.TotalCreated++;  // increments the class-level counter
    }
}

var c1 = new Car("Toyota");
var c2 = new Car("Honda");
Console.WriteLine(Car.TotalCreated); // 2
📚 Key Terms

Class: A blueprint or template that defines the structure (properties) and behaviour (methods) of objects.

Object / Instance: A specific, live copy of a class created with new. Each instance is independent.

Field: A raw variable inside a class. Usually private. Backing storage for properties.

Property: A class member with get and set accessors. The idiomatic C# way to expose data.

Auto-implemented property: public string Name { get; set; } — C# creates the backing field automatically.

Constructor: A special method that runs when an object is created, used to initialise its state.

Static member: Belongs to the class, not any instance. Accessed via the class name, not an object.

var: Lets the compiler infer the variable's type from the right-hand side expression.

Chapter Summary

  • A class is the blueprint; an object (instance) is a real thing created from that blueprint using new.
  • In C#, properties ({ get; set; }) are preferred over raw fields for exposing data.
  • Auto-implemented properties let C# create the backing field automatically — you just write the property.
  • Constructors set up an object's initial state and run automatically when new is called.
  • Multiple objects can be created from one class; each is independent in memory.
  • Computed (expression-bodied) properties derive their value from other properties — no setter needed.
  • Static members belong to the class itself, not individual instances.
