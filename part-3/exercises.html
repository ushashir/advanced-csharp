Part 3 Exercises — ASP.NET Core Basics

These exercises consolidate everything from Part 3: ASP.NET Core fundamentals, Dependency Injection, REST APIs, layered architecture, Entity Framework Core, and configuration management. Some exercises are short quizzes, some require you to write real code, and some ask you to think and design — all valuable skills for a backend developer.

What these exercises cover

  • DI lifetime selection and reasoning
  • REST HTTP verb and status code matching
  • Designing a layered architecture for a real-world scenario
  • Writing a minimal API endpoint from scratch
  • Understanding what a database migration does
  • Designing an appsettings.json configuration structure
  • Writing LINQ queries against a DbContext
  • Reflection: what makes a REST API truly "RESTful"

Exercises

Exercise 3.1 — DI Lifetime Quiz

For each of the following services, select the correct DI lifetime from Transient, Scoped, or Singleton, and write one sentence explaining why.

  1. A NotificationService that sends push notifications to a mobile app. It holds no state between calls and is cheap to create.
  2. An AppDbContext (Entity Framework Core DbContext). It must be consistent within a request but released and recreated for the next.
  3. An InMemoryCache service that stores frequently-read data for the entire life of the application.
  4. A RequestCorrelationService that generates and stores a unique correlation ID for each HTTP request, used for distributed tracing.
  5. A CurrencyConverter that calls an external API to get live exchange rates and caches them for one hour. Multiple requests in that hour should reuse the same rates.

Quick check: What lifetime is appropriate for a DbContext?

Exercise 3.2 — REST Verb & Status Code Matching

Match each API operation to the most appropriate HTTP verb and success status code. Use: GET, POST, PUT, PATCH, DELETE / 200, 201, 204.

Operation Verb Success Code
Retrieve a list of all customers??
Create a new order??
Replace all fields of a product (full update)??
Update only the price of an existing product??
Delete a user account??
Retrieve a single invoice by its ID??

After matching, answer: why does "Create a new order" return 201 rather than 200? What additional information should typically accompany a 201 response?

Exercise 3.3 — Design a Layered Architecture

You are building the backend for a library management system. The system needs to:

  • Allow users to search for books by title, author, or ISBN.
  • Allow staff to add new books and update book details.
  • Allow users to borrow a book — which reduces the available stock and records who borrowed it and when.
  • Send an email to the user confirming their loan.
  • Allow users to return a book — which increases stock and records the return date.
  • Flag overdue books (not returned within 21 days) and send reminder emails.

Design the layered architecture for this system. Your answer should include:

  1. The names of all Controllers, Services, and Repositories you would create.
  2. The interface signatures for at least IBookService and ILoanRepository (method names, parameter types, return types).
  3. What DTOs you would define (at minimum: request DTOs for creating a book and for borrowing a book; response DTOs).
  4. Which services would have DI dependencies on other services (e.g., LoanService depends on IEmailService).
💡 Draw it First

Before writing code, draw a simple box diagram on paper showing the layers and which boxes connect to which. Architecture is best understood visually first. Then translate it into interface signatures.

Exercise 3.4 — Write a Minimal API Endpoint

Using the Minimal API style from Chapter 14, write a complete Program.cs for a simple "Todo List" API with the following endpoints: 

// Endpoints to implement:
// GET  /todos        — return all todos
// GET  /todos/{id}   — return a single todo by id, or 404
// POST /todos        — create a new todo from the request body
// PUT  /todos/{id}   — mark a todo as complete
// DELETE /todos/{id} — delete a todo

Use an in-memory List<TodoItem> as your data store. Define TodoItem with Id, Title, IsComplete, and CreatedAt.

Then answer: if you wanted to add persistence (save todos to a database), what would you need to change? Would any of your endpoint lambdas change?

Exercise 3.5 — What Does a Migration Do?

Explain in your own words — as if explaining to a junior developer who has never used EF Core — what a database migration is, why it is needed, and what happens when you run these two commands: 

dotnet ef migrations add AddUserEmailIndex
dotnet ef database update

Cover all of the following in your explanation:

  • What file(s) are created by migrations add and what do they contain?
  • What does database update do to the running database?
  • What happens if three developers each run migrations add on their own branches before merging?
  • Why are migration files important to commit to source control?
Exercise 3.6 — Configuration Challenge

Design a complete appsettings.json and appsettings.Development.json for a ride-sharing application. The app has the following needs:

  • A SQL Server database for production; SQLite for development.
  • A Google Maps API key (different key for development and production — use "CONFIGURE_VIA_SECRETS" as the placeholder value).
  • Push notification settings: Firebase project ID and server key (secrets — use placeholders).
  • Rate limiting settings: max requests per minute per IP (different in dev vs prod), and whether rate limiting is enabled.
  • Supported country codes list (e.g., ["US", "GB", "NG", "KE"]).

Then: write the corresponding strongly-typed MapsSettings and RateLimitSettings options classes. Show how to register and inject RateLimitSettings using the Options pattern. Write a check in Program.cs that reads the RateLimit:IsEnabled flag and only registers rate-limiting middleware if it is true.

Exercise 3.7 — EF Core LINQ Query Challenge

Given the following entity model (Blog + Post + Tag), write the LINQ queries described below. Each query must be async (using ToListAsync, FirstOrDefaultAsync, etc.). 

public class Blog
{
    public int    Id       { get; set; }
    public string Title    { get; set; } = string.Empty;
    public string AuthorId { get; set; } = string.Empty;
    public List<Post> Posts { get; set; } = new();
}
public class Post
{
    public int      Id          { get; set; }
    public string   Title       { get; set; } = string.Empty;
    public bool     IsPublished { get; set; }
    public int      ViewCount   { get; set; }
    public DateTime PublishedAt { get; set; }
    public int      BlogId      { get; set; }
    public Blog     Blog        { get; set; } = null!;
    public List<Tag> Tags { get; set; } = new();
}
public class Tag
{
    public int    Id    { get; set; }
    public string Name  { get; set; } = string.Empty;
    public List<Post> Posts { get; set; } = new();
}

Write LINQ (EF Core) queries for:

  1. All published posts, ordered by PublishedAt descending, including their blog title. (Use .Include() on the Blog navigation property.)
  2. The top 5 most-viewed published posts.
  3. All blogs that have at least one published post.
  4. Total view count across all published posts in a given blog (given int blogId).
  5. All posts tagged with "csharp" — you'll need to navigate via the Tags collection.
Exercise 3.8 — Reflection: What Makes REST "RESTful"?

The term "REST" is widely used — and widely misunderstood. Many APIs call themselves RESTful while violating several core REST constraints. In this exercise, evaluate the following hypothetical API design and identify which REST constraints it violates: 

// API in question:
// POST /api/getUser?userId=42          ← retrieves a user
// POST /api/doLogin                    ← authenticates, stores session on server
// POST /api/createOrUpdateProduct      ← creates OR updates based on body content
// GET  /api/deleteOrder?orderId=5      ← deletes order 5
// POST /api/processPayment             ← charges a card (no idempotency key)

For each endpoint above:

  1. Name the REST constraint it violates (or multiple violations if applicable).
  2. Propose the correct RESTful design — the verb, URL, and expected status codes.

Finally, write a short paragraph (3–5 sentences) on the difference between an API that uses HTTP methods and JSON versus a truly RESTful API. What is the additional value of the REST constraints (statelessness, uniform interface, resource-based URLs)?

🎯 Connecting Back to the Book

The concepts in Part 3 — middleware, DI, REST, layered architecture, EF Core, configuration — are not isolated topics. They form a complete system. A request comes in through the middleware pipeline, is routed to a controller (REST layer), which calls a service (business logic), which calls a repository (EF Core), which reads config for its connection string (configuration). DI wires all these layers together. Understanding each piece individually is important, but seeing how they interconnect is what turns knowledge into engineering skill.
