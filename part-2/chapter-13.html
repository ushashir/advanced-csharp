Nullable Types — The Empty Seat

Null is one of the most famous concepts — and one of the most notorious sources of bugs — in programming. C# has evolved its approach to null over many versions, and modern C# gives you powerful tools to handle it safely and expressively.

What you'll learn in this chapter

  • Value types vs reference types and their relationship with null
  • Nullable value types — int?, bool?, DateTime?
  • The null-conditional operator ?.
  • The null-coalescing operator ??
  • The null-coalescing assignment operator ??=
  • C# 8 nullable reference types and #nullable enable
  • The null-forgiving operator !
  • Why null is called the "billion-dollar mistake"
  • Practical patterns for safe null handling
🪑 The Empty Seat Analogy

Imagine a train with numbered seats. Seat 12A either has a passenger (a value) or it is empty (null). The seat itself always exists — it is a real location on the train. But whether it holds someone is a separate question.

A nullable type in C# is like that seat. An int? is an integer seat that might or might not be occupied. Before you try to interact with whoever is sitting in the seat, you should check if the seat is actually occupied. Trying to talk to an empty seat — dereferencing a null — causes the programme to crash.

The goal of C#'s nullable type system is to make the compiler enforce that you always check before you use — so you can never accidentally try to talk to an empty seat.

The Billion-Dollar Mistake

In 1965, computer scientist Tony Hoare invented the null reference. In 2009, he publicly called it his "billion-dollar mistake" — because null references have caused countless crashes, security vulnerabilities, and wasted engineering hours ever since.

The core problem: in most languages, any reference variable can be null, but the compiler does not remind you to check. You write customer.Name, forget that customer might be null, and get a NullReferenceException in production at 2am.

Value Types vs Reference Types

In C#, types are either value types or reference types, and this determines whether they can be null by default: 

// Value types — cannot be null by default
int    age      = 25;         // always has a value
bool   active   = true;
double price    = 9.99;
DateTime created = DateTime.Now;

// This won't compile:
// int age = null;  // ERROR — int cannot be null

// Reference types — CAN be null by default (unless nullable reference types enabled)
string name = null;    // allowed — but dangerous
Customer cust = null;  // allowed — but may crash on use

Value types (int, bool, double, struct) live on the stack and always hold a value. Reference types (string, classes, arrays) are references that point to heap memory — and a reference can point to "nothing" (null).

Nullable Value Types — int?

The ? suffix on a value type creates a nullable version of it — a type that can hold the value OR null. This is especially useful for optional fields and database values (where a column might be NULL): 

int?      age      = null;    // int with no value
bool?     consent  = null;    // not yet answered
DateTime? deletedAt = null;   // not yet deleted

// Check for null before using
if (age != null)
    Console.WriteLine($"Age: {age.Value}");

// The .HasValue property is equivalent to != null
if (consent.HasValue)
    Console.WriteLine($"Consent: {consent.Value}");

// Assign a value later
age = 25;
Console.WriteLine(age.Value);  // 25
Console.WriteLine((int) age);   // 25 (explicit cast)

The Null-Conditional Operator (?.)

The ?. operator accesses a member on an object — but only if the object is not null. If it IS null, the whole expression evaluates to null instead of throwing: 

string? name = GetUserName();  // might return null

// Without ?. — crashes if name is null
int len1 = name.Length;  // NullReferenceException if name is null!

// With ?. — safe: returns null if name is null
int? len2 = name?.Length;  // null if name is null, otherwise the length

// Chain multiple ?.  for nested objects
string? city = customer?.Address?.City;
// null if customer is null, or Address is null, or City is null

// Works with method calls too
string? upper = name?.ToUpper();  // null if name is null

// Works with indexers
List<string>? items = GetItems();
string? first = items?.[0];  // null if items is null

The Null-Coalescing Operator (??)

?? provides a default value when something is null. It reads as "if this is null, use that instead": 

string? username = GetStoredUsername();  // might be null

// Old way
string displayName;
if (username != null)
    displayName = username;
else
    displayName = "Anonymous";

// Modern way with ??
string displayName2 = username ?? "Anonymous";

// Chain ?? for multiple fallbacks
string name = GetDisplayName() ?? GetUsername() ?? "Unknown";

// Combine with ?.  for powerful null-safe expressions
string city = customer?.Address?.City ?? "City not specified";
Console.WriteLine(city);  // "City not specified" if anything in the chain is null

// Works with nullable value types too
int age = user.Age ?? 0;  // use 0 if age is null

The Null-Coalescing Assignment Operator (??=)

??= assigns a value to a variable only if that variable is currently null. This is shorthand for "initialise if not already set": 

string? cachedResult = null;

// Long form:
if (cachedResult == null)
    cachedResult = ExpensiveComputation();

// Short form with ??=
cachedResult ??= ExpensiveComputation();

// Great for lazy initialisation
private List<string>? _tags;

public List<string> Tags
{
    get
    {
        _tags ??= new List<string>();  // only creates the list the first time
        return _tags;
    }
}

C# 8 Nullable Reference Types

C# 8 introduced a major safety feature: nullable reference types. When enabled, the compiler tracks which reference types might be null and warns you when you fail to check. This turns the "billion-dollar mistake" from a runtime crash into a compile-time warning. 

// Enable nullable reference types at the top of a file
// (or globally in your .csproj: <Nullable>enable</Nullable>)
#nullable enable

// Without ? — compiler GUARANTEES non-null
string definitelyAString = "hello";

// With ? — compiler knows it MIGHT be null and warns you
string? mightBeNull = GetSomething();

// Safe access required — compiler enforces this
if (mightBeNull != null)
{
    Console.WriteLine(mightBeNull.Length);   // safe — null checked above
}

// Without checking — compiler warning CS8602
Console.WriteLine(mightBeNull.Length);   // WARNING: possible null dereference

The Null-Forgiving Operator (!)

Sometimes you know something is not null, but the compiler does not. The ! postfix operator tells the compiler "trust me, this is not null": 

// The compiler doesn't know GetUser() won't return null here
string? name = GetUser()?.Name;

// We've validated separately and are certain it isn't null
string upper = name!.ToUpper();  // ! suppresses the null warning
💡 Use ! Sparingly

The null-forgiving operator ! does not add any runtime checks — it only silences the compiler warning. If you are wrong and the value IS null, you will still get a NullReferenceException at runtime. Use ! only when you are genuinely certain and can explain why. Prefer null checks, ??, or pattern matching instead.

Practical Null-Handling Patterns

Here is how modern C# handles null in practice for common scenarios: 

// 1. Guard clause — fail fast at the top of a method
public void ProcessOrder(Order? order)
{
    ArgumentNullException.ThrowIfNull(order);
    // order is guaranteed non-null from here on
    Console.WriteLine(order.Id);
}

// 2. Pattern matching with is null check
if (user is not null)
{
    Console.WriteLine(user.Name);
}

// 3. Null-safe method call
string name = user?.FullName ?? "Unknown";

// 4. Null-safe LINQ — filter out nulls
List<string?> names = ["Alice", null, "Bob", null];
List<string> nonNull = names
    .Where(n => n is not null)
    .Select(n => n!)    // safe use of ! — we just filtered out nulls
    .ToList();

// 5. Returning null from a method — signal absence cleanly
public Customer? FindByEmail(string email)
    => _customers.FirstOrDefault(c => c.Email == email);
🎓 The Billion-Dollar Mistake — Tony Hoare's Regret

"I call it my billion-dollar mistake. It was the invention of the null reference in 1965. At that time, I was designing the first comprehensive type system for references in an object-oriented language. I couldn't resist the temptation to put in a null reference, simply because it was so easy to implement. This has led to innumerable errors, vulnerabilities, and system crashes, which have probably caused a billion dollars of pain and damage in the last forty years."

— Sir Tony Hoare, QCon London 2009

Languages like Kotlin, Swift, and Rust were designed from scratch with null safety. C# 8's nullable reference types retrofit the same guarantee onto an existing language — a significant achievement.

📚 Key Terms

Null: The absence of a value. A reference that points to nothing.

int? (Nullable<int>): A value type that can hold an int value OR null. Any value type can become nullable with the ? suffix.

?. (null-conditional operator): Accesses a member safely — returns null instead of throwing if the object is null.

?? (null-coalescing operator): Returns the left operand if it is not null, otherwise returns the right operand (the default value).

??= (null-coalescing assignment): Assigns the right operand to the variable only if the variable is currently null.

Nullable reference types: A C# 8+ feature that makes the compiler track and warn about potential null dereferences on reference types. Enabled with #nullable enable or in the project file.

! (null-forgiving operator): Tells the compiler to suppress null warnings for a specific expression. Does not add runtime safety — use carefully.

NullReferenceException: The runtime error thrown when you try to access a member on a null reference. The error the nullable type system exists to prevent.

Chapter Summary

  • Value types (int, bool, struct) cannot be null by default. Add ? to create a nullable version: int?.
  • Reference types (string, classes) can be null — this is the source of most NullReferenceException crashes.
  • ?. (null-conditional) accesses members safely without crashing on null.
  • ?? (null-coalescing) provides a fallback value when an expression is null.
  • ??= assigns a value only when the variable is currently null — great for lazy initialisation.
  • C# 8's #nullable enable makes the compiler warn you when you forget to check for null on reference types.
  • The null-forgiving operator ! suppresses compiler warnings — use it only when you are certain and have a good reason.
  • Tony Hoare called null the "billion-dollar mistake." Modern C# aims to eliminate null bugs at compile time.

You have this class representing a user profile (some fields may not be filled in): 

public class UserProfile
{

    public string?   DisplayName { get; set; }
    public string?   Bio         { get; set; }

    public Address?  Location    { get; set; }
}

public class Address
{
    public string? City    { get; set; }
    public string? Country { get; set; }
}

Write a method FormatProfile(UserProfile? profile) that returns a formatted multi-line string using all the null-safe operators (?., ??, ??=) to handle missing data gracefully. If profile itself is null, return "No profile available.". For missing fields, show "Not provided". For the location, show "City, Country" or just the available part if only one is present.
