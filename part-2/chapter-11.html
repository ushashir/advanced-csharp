LINQ — The Query Language Built Into C#

LINQ (Language Integrated Query) is one of the most beloved features in C#. It gives you a powerful, readable way to filter, sort, transform, and aggregate any collection of data — in a single expressive line of code.

What you'll learn in this chapter

  • What LINQ is and the problem it solves
  • Method syntax vs query syntax — two ways to write the same LINQ
  • Core LINQ methods: Where, Select, OrderBy
  • Aggregation: Count, Sum, Average, Min, Max
  • Element access: First, FirstOrDefault, Any, All
  • Grouping with GroupBy
  • How LINQ works on any IEnumerable<T> — including database queries
🗂️ The Personal Assistant Analogy

Imagine you have a personal assistant who can handle any list of things for you. You say: "From my contact list, give me everyone in Lagos, sorted by surname, but only show me their names and phone numbers."

Without an assistant, you would write a loop, add an if-statement, build a temporary list, then sort it manually. With LINQ, you express the intent directly: .Where(c => c.City == "Lagos").OrderBy(c => c.Surname).Select(c => new { c.Name, c.Phone }). The assistant figures out the details. You just describe what you want.

Setup: A Products List

All the examples in this chapter use a list of products. Here is the model and data: 

public record Product(
    string  Name,
    string  Category,
    decimal Price,
    int     Stock,
    bool    IsAvailable
);

List<Product> products =
[
    new("Laptop Pro",     "Electronics", 1299.99m, 15, true),
    new("Wireless Mouse", "Electronics",   29.99m, 200, true),
    new("Desk Chair",     "Furniture",    349.00m,  8, true),
    new("Standing Desk",  "Furniture",    799.00m,  3, true),
    new("Notebook",       "Stationery",     4.99m, 500, true),
    new("USB Hub",        "Electronics",   49.99m,  0, false),
    new("Ergonomic Pad",  "Furniture",     24.99m, 45, true),
    new("Whiteboard",     "Stationery",    89.99m,  12, true),
];

Where — Filtering

Where keeps only the elements that satisfy a condition: 

// Products that are in stock and available
var available = products
    .Where(p => p.IsAvailable && p.Stock > 0)
    .ToList();

// Electronics over £50
var expensiveElectronics = products
    .Where(p => p.Category == "Electronics" && p.Price > 50m)
    .ToList();

foreach (var p in expensiveElectronics)
    Console.WriteLine($"{p.Name}: £{p.Price}");
// Laptop Pro: £1299.99

Select — Transforming

Select projects each element into a new form — like SQL's SELECT clause: 

// Get just the names
IEnumerable<string> names = products.Select(p => p.Name);

// Project to an anonymous type with only the fields you need
var catalogue = products
    .Where(p => p.IsAvailable)
    .Select(p => new { p.Name, p.Price, p.Category })
    .ToList();

foreach (var item in catalogue)
    Console.WriteLine($"{item.Name} ({item.Category}) — £{item.Price}");

// Apply a transformation: increase all prices by 10%
var pricesRaised = products.Select(p => p with { Price = p.Price * 1.1m });

OrderBy and ThenBy — Sorting

// Sort by price ascending
var byPrice = products.OrderBy(p => p.Price).ToList();

// Sort by category, then by price descending within each category
var sorted = products
    .OrderBy(p => p.Category)
    .ThenByDescending(p => p.Price)
    .ToList();

foreach (var p in sorted)
    Console.WriteLine($"{p.Category,-15} {p.Name,-20} £{p.Price,8:F2}");

Aggregation Methods

int     total    = products.Count();
int     inStock  = products.Count(p => p.Stock > 0);
decimal sumPrice = products.Sum(p => p.Price);
decimal avgPrice = products.Average(p => p.Price);
decimal maxPrice = products.Max(p => p.Price);
decimal minPrice = products.Min(p => p.Price);

Console.WriteLine($"Total products: {total}");
Console.WriteLine($"In stock: {inStock}");
Console.WriteLine($"Total catalogue value: £{sumPrice:F2}");
Console.WriteLine($"Average price: £{avgPrice:F2}");
Console.WriteLine($"Most expensive: £{maxPrice:F2}");
Console.WriteLine($"Cheapest: £{minPrice:F2}");

First, Any, All

// First matching element — throws if none found
Product cheapest = products.OrderBy(p => p.Price).First();

// FirstOrDefault — returns null if none found (safe)
Product? laptop = products.FirstOrDefault(p => p.Name.Contains("Laptop"));

// Any — does at least one element match?
bool hasOutOfStock = products.Any(p => p.Stock == 0);  // true

// All — do ALL elements match?
bool allAvailable = products.All(p => p.IsAvailable);  // false

Console.WriteLine($"Has out-of-stock items: {hasOutOfStock}");
Console.WriteLine($"All available: {allAvailable}");

GroupBy

GroupBy organises elements into named groups — like SQL's GROUP BY: 

// Group products by category and count each group
var byCategory = products
    .GroupBy(p => p.Category)
    .Select(g => new
    {
        Category = g.Key,
        Count    = g.Count(),
        AvgPrice = g.Average(p => p.Price)
    })
    .OrderBy(g => g.Category);

foreach (var group in byCategory)
    Console.WriteLine($"{group.Category}: {group.Count} items, avg £{group.AvgPrice:F2}");
// Electronics: 3 items, avg £459.99
// Furniture: 3 items, avg £391.00
// Stationery: 2 items, avg £47.49

Method Syntax vs Query Syntax

LINQ has two syntaxes. They compile to exactly the same code — use whichever you find more readable: 

// Method syntax — most common in modern C#
var resultMethod = products
    .Where(p => p.Category == "Electronics")
    .OrderBy(p => p.Price)
    .Select(p => p.Name);

// Query syntax — reads more like SQL
var resultQuery =
    from p in products
    where p.Category == "Electronics"
    orderby p.Price
    select p.Name;

// Both produce identical results
💡 Which Syntax Should I Use?

Most modern C# uses method syntax. It is more composable (easy to chain operations), and many LINQ methods like Count(), Sum(), and GroupBy() have no query-syntax equivalent. Query syntax can be clearer for complex joins. For this book, we use method syntax throughout.

LINQ and Deferred Execution

LINQ queries are lazy — they don't execute until you actually iterate the results. This is called deferred execution. Calling .ToList(), .ToArray(), or iterating with foreach triggers execution. 

// This does NOT query yet — just builds the query description
var query = products.Where(p => p.Price > 100m);

// Execution happens here (when iterating)
foreach (var p in query)
    Console.WriteLine(p.Name);

// .ToList() forces immediate execution and stores results in memory
List<Product> snapshot = query.ToList();  // executes now

LINQ Works on Databases Too

LINQ works on any IEnumerable<T> or IQueryable<T>. Entity Framework Core (covered in Chapter 18) lets you write LINQ queries against a database and it translates them into SQL automatically: 

// LINQ on in-memory list (IEnumerable)
var result = products.Where(p => p.Price > 100m).ToList();

// LINQ on a database table (IQueryable — via Entity Framework Core)
// The C# code looks identical — EF Core translates it to SQL:
// SELECT * FROM Products WHERE Price > 100
var dbResult = context.Products.Where(p => p.Price > 100m).ToList();
📚 Key Terms

LINQ: Language Integrated Query — a set of extension methods on IEnumerable<T> that provide a uniform way to query and transform data collections in C#.

Where: Filters a sequence to include only elements matching a predicate.

Select: Projects each element of a sequence into a new form (transformation).

OrderBy / OrderByDescending: Sorts elements ascending or descending.

GroupBy: Groups elements by a key selector, returning groups with a Key property.

Deferred execution: LINQ queries are not evaluated until iterated. Calling ToList() or ToArray() forces immediate evaluation.

Lambda expression: The p => p.Price > 100 syntax used inside LINQ methods. Covered in detail in Chapter 12.

Chapter Summary

  • LINQ is a set of extension methods on IEnumerable<T> for filtering, transforming, sorting, and aggregating data.
  • Where filters, Select transforms, OrderBy sorts.
  • Aggregation methods: Count, Sum, Average, Min, Max.
  • First/FirstOrDefault get one element; Any/All test conditions.
  • GroupBy creates named groups — like SQL's GROUP BY.
  • Method syntax and query syntax produce identical code; modern C# prefers method syntax.
  • LINQ is lazy (deferred execution) — queries run only when iterated or forced with ToList().
  • Entity Framework Core translates LINQ into SQL — the same C# code queries both in-memory lists and databases.
