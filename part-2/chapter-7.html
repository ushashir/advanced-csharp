Generics — One Box, Any Label

Generics are one of the most powerful features in C#. They let you write a single class or method that works with any type — without sacrificing type safety or performance. Once you understand generics, you will wonder how you ever coded without them.

What you'll learn in this chapter

  • Why generics exist and what problem they solve
  • How to write a generic class with a type parameter <T>
  • How to write generic methods
  • How to constrain type parameters with where
  • The most important built-in generic types: List<T>, Dictionary<TKey,TValue>
  • A complete generic Stack<T> implementation

The Label Maker Analogy

Imagine a label maker — a small handheld device that prints labels. The machine itself does not care what word you type into it. You type "FRAGILE" and it prints "FRAGILE." You type "KITCHEN" and it prints "KITCHEN." The machine is the same; only the input changes. The output is always a correctly formatted label.

A generic class or method in C# is exactly like that label maker. You write the logic once. You then tell it what type to work with at the moment you use it. The compiler stamps out a perfect, type-safe version for that specific type.

🏷️ The Label Maker Analogy

The label maker doesn't care whether you're labelling a box of books or a box of spices. It prints whatever you give it. A generic class Box<T> doesn't care whether T is a string, an int, or a Customer object — it stores and retrieves it correctly either way.

The key insight: you write the logic once, and the compiler creates the type-safe version for each T you use. No duplication. No casting. No runtime errors.

The Problem Generics Solve

Before generics (C# 1.0), developers stored things in ArrayList, which held everything as object. Every time you read something back, you had to cast it: 

// Before generics — fragile and error-prone
ArrayList list = new ArrayList();
list.Add(42);
list.Add("oops, a string");   // compiler allows this — it's just "object"

int value = (int) list[0];        // requires an explicit cast
int broken = (int) list[1];      // compiles fine — crashes at runtime!

This is a runtime failure caused by a bug the compiler was perfectly happy with. Generics eliminate this entire class of problem by making the type part of the declaration: 

// After generics — safe and clean
List<int> list = new List<int>();
list.Add(42);
list.Add("oops");   // COMPILER ERROR — won't even compile. Bug caught instantly.

int value = list[0];  // no cast needed — the compiler knows it's an int
📚 Key Term: Type Parameter

A type parameter is a placeholder for a real type, written inside angle brackets like <T>. The letter T is convention (short for "Type") but you can use any name. When you use the generic class, you replace T with a concrete type like string or int. The compiler then generates a version of the class that uses that exact type everywhere.

Writing Your First Generic Class

Let's write a simple Box<T> class — a container that holds one item of any type: 

public class Box<T>
{
    private T _item;

    public Box(T item)
    {
        _item = item;
    }

    public T GetItem()
    {
        return _item;
    }

    public void SetItem(T newItem)
    {
        _item = newItem;
    }

    public override string ToString()
        => $"Box<{typeof(T).Name}> containing: {_item}";
}

// Usage
var intBox = new Box<int>(42);
var nameBox = new Box<string>("Ada Lovelace");

Console.WriteLine(intBox);    // Box<Int32> containing: 42
Console.WriteLine(nameBox);   // Box<String> containing: Ada Lovelace

The same class definition handles both. No casting. No code duplication. The compiler generates two separate versions internally — one for int, one for string — each perfectly type-safe.

Generic Methods

You do not have to make the whole class generic. You can make individual methods generic instead. This is useful when only one specific operation needs type flexibility: 

public class Utilities
{
    // A generic method — T is declared on the method itself
    public static void Swap<T>(ref T a, ref T b)
    {
        T temp = a;
        a = b;
        b = temp;
    }

    public static T Max<T>(T a, T b) where T : IComparable<T>
    {
        return a.CompareTo(b) >= 0 ? a : b;
    }
}

// Usage
int x = 10, y = 20;
Utilities.Swap(ref x, ref y);
Console.WriteLine($"x={x}, y={y}");   // x=20, y=10

string biggest = Utilities.Max("apple", "banana");
Console.WriteLine(biggest);  // banana (alphabetically larger)

Generic Constraints

Sometimes you need to restrict what type T can be — for example, you might need to call a method on T, which only makes sense if T implements the right interface. The where keyword lets you add constraints: 

// T must be a reference type (class)
public class Repository<T> where T : class
{
    private List<T> _items = new();

    public void Add(T item) => _items.Add(item);
    public T? FindFirst() => _items.FirstOrDefault();
}

// T must have a public parameterless constructor
public class Factory<T> where T : new()
{
    public T Create() => new T();  // only works because of the new() constraint
}

// T must implement IComparable<T> — so we can compare instances
public T FindMin<T>(IEnumerable<T> items) where T : IComparable<T>
{
    T min = items.First();
    foreach (var item in items)
        if (item.CompareTo(min) < 0) min = item;
    return min;
}

The most common constraints are:

  • where T : class — T must be a reference type
  • where T : struct — T must be a value type
  • where T : new() — T must have a parameterless constructor
  • where T : SomeBaseClass — T must inherit from SomeBaseClass
  • where T : ISomeInterface — T must implement ISomeInterface
  • where T : IComparable<T> — T must be comparable (allows sorting)

Built-In Generic Types

The .NET Base Class Library is full of generic types you will use constantly. The two most important are List<T> and Dictionary<TKey,TValue>: 

// List<T> — a resizable array
List<string> names = new List<string> { "Alice", "Bob", "Charlie" };
names.Add("Diana");
names.Remove("Bob");
Console.WriteLine(names.Count);  // 3

// Dictionary<TKey,TValue> — a key/value map
Dictionary<string, int> scores = new()
{
    { "Alice", 95 },
    { "Bob", 87 }
};
scores["Charlie"] = 91;
Console.WriteLine(scores["Alice"]);  // 95

We will cover the full collection library in Chapter 8. For now, notice that both are generic — they express their type requirements in angle brackets, giving you full type safety and IntelliSense.

⚡ Performance Note

Generic collections are significantly faster than their non-generic equivalents (ArrayList, Hashtable) for value types like int and struct. The reason is boxing: storing a value type in an object requires allocating heap memory to wrap it. Generics avoid this entirely — the JIT compiler generates code that works directly with the value type. This is why you will never see ArrayList in modern C# code.

A Complete Generic Stack<T>

Let's build something practical — a generic stack (last-in, first-out container) to see how generics compose with real data structures: 

public class Stack<T>
{
    private readonly List<T> _items = new();

    public int Count => _items.Count;
    public bool IsEmpty => _items.Count == 0;

    public void Push(T item)
    {
        _items.Add(item);
    }

    public T Pop()
    {
        if (IsEmpty)
            throw new InvalidOperationException("Stack is empty.");
        T item = _items[_items.Count - 1];
        _items.RemoveAt(_items.Count - 1);
        return item;
    }

    public T Peek()
    {
        if (IsEmpty)
            throw new InvalidOperationException("Stack is empty.");
        return _items[_items.Count - 1];
    }
}

// Works with strings
var history = new Stack<string>();
history.Push("page-1");
history.Push("page-2");
history.Push("page-3");
Console.WriteLine(history.Pop());  // page-3
Console.WriteLine(history.Peek()); // page-2 (still in stack)

// Exact same class works with integers
var numbers = new Stack<int>();
numbers.Push(10);
numbers.Push(20);
Console.WriteLine(numbers.Pop());  // 20

One class definition, infinite reuse. That is the power of generics.

💡 Generic Naming Conventions

When using a single type parameter, name it T by convention. For multiple type parameters, use descriptive names prefixed with T: TKey, TValue, TInput, TResult. Avoid single letters for multiple parameters — Dictionary<TKey, TValue> is much clearer than Dictionary<K, V>.

📚 Key Terms

Generic: A class or method that is parameterised by one or more types, written as ClassName<T>.

Type parameter: The placeholder (e.g. T) that stands in for a real type until the generic is used.

Constraint: A restriction on what types a type parameter can be, declared with the where keyword.

Boxing: The process of wrapping a value type in an object on the heap. Generics avoid boxing for value types, which is why they are faster than non-generic collections.

Type inference: When the compiler deduces the type parameter automatically from context, so you can write Swap(ref x, ref y) instead of Swap<int>(ref x, ref y).

Chapter Summary

  • Generics let you write one class or method that works correctly with any type.
  • Type parameters (written as <T>) are placeholders replaced by real types at compile time.
  • Generics provide full type safety — mistakes are caught by the compiler, not at runtime.
  • Generic methods can infer their type parameter from the arguments you pass.
  • The where keyword adds constraints on what types T can be.
  • Generic collections like List<T> are faster than non-generic collections because they avoid boxing.
  • The naming convention is T for a single parameter, and TKey/TValue style for multiple parameters.

  • Properties First (type TFirst) and Second (type TSecond)

  • A method Swap() that returns a new Pair<TSecond, TFirst> with the values reversed
