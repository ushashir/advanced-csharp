Delegates & Lambdas — The Callback Menu

In C#, methods are first-class citizens — you can store references to them in variables, pass them as arguments, and invoke them later. Delegates are the type-safe wrapper that makes this possible. Lambdas are the elegant shorthand for writing those methods inline.

What you'll learn in this chapter

  • What a delegate is and how to declare one
  • The built-in delegate types: Func<T,TResult>, Action<T>, Predicate<T>
  • Lambda expressions and the => arrow syntax
  • Closures — how lambdas capture variables from their surroundings
  • Events as multicast delegates
  • How LINQ uses Func<T,bool> under the hood
  • A simple event system with EventHandler
📞 The Callback Analogy

Imagine calling a taxi company and saying "when the taxi arrives, call me on this number." You give them your phone number — a reference to the "call me" action — and carry on with your day. Later, the taxi company uses that reference to reach you at exactly the right moment.

A delegate is like giving someone your phone number. It is a stored reference to a method. You pass it to some code, and that code calls your method back when the time is right. The famous pattern for this is called a callback. LINQ does exactly this — you pass a function to Where, and LINQ calls it back for every element.

Declaring and Using a Delegate

A delegate declaration defines a method signature. Any method that matches the signature can be assigned to that delegate type: 

// Declare a delegate type (like a "method type")
public delegate int MathOperation(int a, int b);

// Methods that match the signature
static int Add(int a, int b) => a + b;
static int Multiply(int a, int b) => a * b;

// Create delegate instances pointing to the methods
MathOperation operation = Add;
Console.WriteLine(operation(3, 4));  // 7

operation = Multiply;
Console.WriteLine(operation(3, 4));  // 12

// Pass a delegate as a method argument
static void PrintResult(MathOperation op, int x, int y)
    => Console.WriteLine($"Result: {op(x, y)}");

PrintResult(Add, 10, 5);       // Result: 15
PrintResult(Multiply, 10, 5);  // Result: 50

Built-In Delegate Types

You almost never need to declare your own delegate type. .NET provides three generic delegate types that cover virtually every case: 

// Func<TResult> — takes no params, returns TResult
Func<string> greeting = () => "Hello, World!";
Console.WriteLine(greeting());  // Hello, World!

// Func<T, TResult> — takes one param of type T, returns TResult
Func<int, string> intToStr = n => $"Number {n}";
Console.WriteLine(intToStr(42));  // Number 42

// Func<T1, T2, TResult> — takes two params, returns TResult
Func<int, int, int> add = (a, b) => a + b;
Console.WriteLine(add(3, 4));   // 7

// Action — takes no params, returns void
Action sayHi = () => Console.WriteLine("Hi!");
sayHi();  // Hi!

// Action<T> — takes one param, returns void
Action<string> printLine = msg => Console.WriteLine(msg);
printLine("Hello from Action!");

// Predicate<T> — takes T, returns bool (same as Func<T, bool>)
Predicate<int> isEven = n => n % 2 == 0;
Console.WriteLine(isEven(4));  // True
Console.WriteLine(isEven(7));  // False
💡 Func, Action, or Predicate?

Func<..., TResult> — use when the delegate returns a value. The last type parameter is always the return type.
Action<...> — use when the delegate returns nothing (void).
Predicate<T> — use specifically for a true/false test on a value of type T. Under the hood it's just Func<T, bool>, but the name is more expressive. Used by older APIs like List<T>.Find().

Lambda Expressions

A lambda expression is an anonymous function defined inline using the => (arrow) operator. Instead of declaring a separate named method, you write the logic where you need it: 

// Expression lambda (single expression — implicit return)
Func<int, int> square = x => x * x;

// Statement lambda (multiple statements — explicit return)
Func<int, string> classify = n =>
{
    if (n < 0) return "negative";
    if (n == 0) return "zero";
    return "positive";
};

Console.WriteLine(square(5));      // 25
Console.WriteLine(classify(-3));   // negative
Console.WriteLine(classify(0));    // zero
Console.WriteLine(classify(7));    // positive

Closures — Capturing Variables

A lambda can close over (capture) variables from the surrounding scope. The lambda retains a reference to those variables — even after the outer method returns: 

static Func<int> MakeCounter()
{
    int count = 0;  // captured by the lambda below
    return () => ++count;
}

var counter = MakeCounter();
Console.WriteLine(counter());  // 1
Console.WriteLine(counter());  // 2
Console.WriteLine(counter());  // 3

// Each call increments the same "count" variable.
// The lambda keeps it alive even though MakeCounter() returned.

How LINQ Uses Func Under the Hood

Now you can understand how LINQ methods work. Where takes a Func<T, bool> — a function that tests each element and returns true or false. Select takes a Func<T, TResult> — a transformation function: 

// What LINQ's Where signature actually looks like:
// public static IEnumerable<T> Where<T>(
//     this IEnumerable<T> source,
//     Func<T, bool> predicate)

List<int> numbers = [1, 2, 3, 4, 5, 6];

// Lambda passed to Where is a Func<int, bool>
var evens = numbers.Where(n => n % 2 == 0).ToList();  // [2, 4, 6]

// Lambda passed to Select is a Func<int, string>
var labels = numbers.Select(n => $"Item {n}").ToList();
// ["Item 1", "Item 2", ...]

// You can store the lambda separately and reuse it
Func<int, bool> isEven = n => n % 2 == 0;
var evens2 = numbers.Where(isEven).ToList();

Events — Multicast Delegates

An event is a special kind of multicast delegate. Multiple handlers can subscribe (+=), and when the event fires, all of them are called. This is the backbone of GUI programming, ASP.NET middleware, and the Observer pattern. 

public class Button
{
    // Declare an event using the built-in EventHandler delegate
    public event EventHandler<EventArgs>? Clicked;

    public void SimulateClick()
    {
        Console.WriteLine("Button clicked!");
        // Raise the event — all subscribers are notified
        Clicked?.Invoke(this, EventArgs.Empty);
    }
}

// Usage — subscribe to the event
var btn = new Button();

// Subscribe handler 1
btn.Clicked += (sender, e) =>
    Console.WriteLine("Logger: button was clicked");

// Subscribe handler 2
btn.Clicked += (sender, e) =>
    Console.WriteLine("Analytics: recording click event");

btn.SimulateClick();
// Button clicked!
// Logger: button was clicked
// Analytics: recording click event

// Unsubscribe with -=
// btn.Clicked -= handlerReference;
📚 Key Terms

Delegate: A type-safe reference to a method. Defined with the delegate keyword. Acts as a strongly-typed function pointer.

Func<..., TResult>: A built-in generic delegate for methods that return a value. The last type parameter is the return type.

Action<...>: A built-in generic delegate for methods that return void.

Predicate<T>: A built-in delegate for a test method that takes T and returns bool. Equivalent to Func<T, bool>.

Lambda expression: An anonymous function written inline with => syntax. x => x * x is a lambda that squares its input.

Closure: A lambda that captures variables from the surrounding scope, keeping them alive even after the outer method returns.

Event: A multicast delegate that allows multiple subscribers to be notified when something happens. Declared with the event keyword.

Multicast delegate: A delegate that holds references to more than one method. Calling it invokes all registered methods in order.

Chapter Summary

  • A delegate is a type-safe reference to a method — it lets you store and pass methods like variables.
  • The built-in delegate types Func, Action, and Predicate cover almost every use case — you rarely need to declare your own.
  • Lambda expressions (=>) are inline anonymous methods — the syntax you see inside LINQ calls.
  • Closures let lambdas capture and hold onto variables from the surrounding scope.
  • LINQ methods like Where and Select accept Func delegates — this is why lambdas work so naturally with LINQ.
  • Events are multicast delegates — multiple handlers can subscribe and all are called when the event fires.
  • Use += to subscribe and -= to unsubscribe from an event.
