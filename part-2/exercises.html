Part 2 Exercises — Advanced C# Concepts

These exercises cover everything from Part 2: Generics, Collections, Exception Handling, Interfaces, LINQ, Delegates & Lambdas, and Nullable Types. Work through them in order — each one builds on the concepts you have studied. Some are code challenges, some are written reflections, and some are interactive quizzes.

What these exercises cover

  • Generics — fixing and extending a broken generic class
  • LINQ — filtering, transforming, and chaining queries on real data
  • Collections — choosing the right collection type for the job
  • Exception handling — structured try/catch/finally patterns
  • Custom exceptions — designing your own exception hierarchy
  • Delegates & Lambdas — writing expressive functional-style code
  • Nullable types — safe null handling with ? and ?? operators
  • Reflection — synthesising what you have learned

Exercises

Exercise 2.1 — Fix the Broken Generic Class

The following generic class has three bugs. Identify and fix each one:

// Buggy version — do NOT copy this directly!
public class Stack<T>
{
    private T[] _items = new T[10];
    private int _count = 0;

    public void Push(string item)   // Bug 1
    {
        _items[_count] = item;
        _count++;
    }

    public T Pop()
    {
        if (_count == 0)
            return default;          // Bug 2 — how should we signal empty?

        _count--;
        return _items[_count + 1];  // Bug 3
    }

    public int Count => _count;
}

After fixing all three bugs, add a Peek() method that returns the top item without removing it, and a IsEmpty property. Then write a small test that pushes three integers, peeks at the top, then pops all three and prints each one.

💡 Hint

Bug 1: the parameter type should use the type parameter T, not a concrete type. Bug 2: when the stack is empty you should throw an InvalidOperationException rather than silently returning a default value — callers need to know something went wrong. Bug 3: check the index arithmetic carefully after decrementing.

Exercise 2.2 — LINQ Challenge: Filter and Transform

You have the following list of products. Using LINQ method syntax (not query syntax), write the queries described below. 

var products = new List<Product>
{
    new Product { Name = "Laptop",    Price = 1200.00m, Category = "Electronics", InStock = true  },
    new Product { Name = "Desk Chair", Price =  350.00m, Category = "Furniture",    InStock = true  },
    new Product { Name = "Monitor",   Price =  450.00m, Category = "Electronics", InStock = false },
    new Product { Name = "Keyboard",  Price =   89.99m, Category = "Electronics", InStock = true  },
    new Product { Name = "Bookshelf", Price =  199.00m, Category = "Furniture",    InStock = true  },
    new Product { Name = "Mouse",     Price =   39.99m, Category = "Electronics", InStock = true  },
};

Write individual LINQ queries to answer each of the following:

  1. Get all in-stock Electronics products, sorted by price descending.
  2. Get the names of all products priced under $200, as a List<string>.
  3. Calculate the total value of all in-stock products (sum of prices).
  4. Find the most expensive product overall. Use MaxBy.
  5. Group all products by category. For each group, print the category name and the average price.
  6. Check whether any product is out of stock. Check whether all electronics are in stock.
🔎 LINQ Reminder

For grouping, remember: .GroupBy(p => p.Category) returns an IEnumerable<IGrouping<string, Product>>. You can iterate each group with a foreach, and each group has a Key property (the category name) plus all its members.

Exercise 2.3 — Collection Selection Quiz

For each scenario below, name the most appropriate .NET collection type and explain why. Choose from: List<T>, Dictionary<TKey, TValue>, HashSet<T>, Queue<T>, Stack<T>, SortedDictionary<TKey, TValue>, LinkedList<T>.

  1. You are building a job processing system. Jobs must be processed in the order they arrive (first in, first out).
  2. You need to track which usernames have already been taken. Lookups must be O(1) and you don't need duplicates.
  3. You are implementing an "undo" feature in a text editor. The most recently made change must be reversed first.
  4. You need to cache user profiles by their user ID (integer), looking them up by ID in O(1) time.
  5. You are maintaining a leaderboard where players are always sorted by score. New entries should remain sorted automatically.
  6. You want a simple ordered list of items that you will iterate over frequently and occasionally add/remove at the end.

Quick check: What collection type provides O(1) average-case lookup by a unique key?

Exercise 2.4 — Exception Handling Practice

The following method reads a number from the user, divides 100 by it, and prints the result. It has no error handling at all. Rewrite it with proper exception handling: 

// Original — no error handling
static void DivideByUserInput()
{
    Console.Write("Enter a number: ");
    string input = Console.ReadLine();
    int number = int.Parse(input);
    int result = 100 / number;
    Console.WriteLine($"100 / {number} = {result}");
}

Your rewritten version must:

  • Catch FormatException if the user types something that isn't a number, printing a friendly message.
  • Catch DivideByZeroException if the user enters 0, printing a different friendly message.
  • Use a finally block to always print "Thank you for using the calculator."
  • Use int.TryParse instead of int.Parse as an alternative approach — rewrite a second version using TryParse and explain the trade-offs.
Exercise 2.5 — Write a Custom Exception

Design a custom exception hierarchy for an online banking application. The base exception should be BankingException. Derive at least three specific exceptions from it: one for insufficient funds, one for an invalid account number, and one for a daily withdrawal limit being exceeded.

Each exception class should:

  • Inherit from BankingException (which itself inherits from Exception).
  • Include a meaningful constructor that passes a descriptive message to the base.
  • The InsufficientFundsException should carry two extra properties: RequestedAmount (decimal) and AvailableBalance (decimal), so callers can log exactly what happened.

Then write a Withdraw(decimal amount) method on a fake BankAccount class that throws the appropriate exception in each error case. Show a usage example catching the specific exception types in the correct order (most specific first).

📚 Reminder: Exception Hierarchy Matters

Always catch more specific exceptions before more general ones. If you catch BankingException before InsufficientFundsException, the specific catch block will never be reached — the compiler may warn you, but it's still a logical bug in your intent.

Exercise 2.6 — Lambda Expression Challenge

Convert each of the following traditional delegate/method usages into concise lambda expressions. Then go one step further and chain them where possible. 

// Part A — Convert this named method to a lambda assigned to a Func<>
static bool IsEven(int n) => n % 2 == 0;

// Part B — Convert this to an Action<string> lambda
static void PrintUpperCase(string s)
{
    Console.WriteLine(s.ToUpper());
}

// Part C — Convert this to a Func<int, int, int> lambda
static int Multiply(int a, int b) => a * b;

After converting all three, write a method called ApplyTwice that takes a Func<int, int> and an int, and applies the function twice. For example, ApplyTwice(x => x * 2, 3) should return 12 (3 × 2 = 6, then 6 × 2 = 12).

Finally, use ApplyTwice with three different lambdas: double the value, add 10, and square the value. Print the results.

Exercise 2.7 — Nullable Handling

The method below has several potential null reference problems. Identify each one and rewrite the method using nullable reference types, the null-conditional operator (?.), the null-coalescing operator (??), and null-coalescing assignment (??=) where appropriate. 

// Risky version
public static string FormatUserDisplay(User user)
{
    string name = user.Profile.DisplayName;
    string city = user.Profile.Address.City;
    string bio  = user.Bio;

    return $"{name} from {city}: {bio}";
}

// Assume these types:
public class User   { public Profile? Profile { get; set; } public string? Bio { get; set; } }
public class Profile { public string? DisplayName { get; set; } public Address? Address { get; set; } }
public class Address { public string? City { get; set; } }

Your safe version should:

  • Return "Anonymous" if the display name is null.
  • Return "Unknown location" if the city is null or if Address or Profile is null.
  • Return "No bio provided" if Bio is null.
  • Never throw a NullReferenceException regardless of which properties are null.

Quick check: What operator do you use to safely access a property that might be null, returning null instead of throwing?

Exercise 2.8 — Reflection: Advanced C# in the Real World

This is an open-ended written exercise. Pick two of the following real-world scenarios and describe, in 2–4 paragraphs each, which C# features from Part 2 you would use and why.

  1. An e-commerce recommendation engine that takes a list of a user's past purchases (each with a category, price, and date) and produces a ranked list of recommendations from a product catalogue.
  2. A file import service that reads CSV files from different sources, each with a different schema, and maps them all to a common internal model. Some files may be malformed; the service must log errors without crashing.
  3. An event notification system that allows any part of the application to subscribe to events (like "order placed" or "payment received") and react asynchronously — for example, by sending an email or updating a dashboard.

In your answer, explicitly mention: which generic collection types you would use and why, how LINQ would simplify the data queries, how you would handle errors robustly, and how delegates or lambdas might feature in your design.

🎯 What a Strong Answer Looks Like

A strong answer doesn't just name the features — it justifies why each one is the right tool. "I would use a Dictionary<string, List<Product>> to group products by category because dictionary lookups are O(1) and I'll be accessing categories repeatedly during scoring…" is much better than "I would use a Dictionary and LINQ."
