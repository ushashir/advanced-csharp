Collections — C#'s Toolbox

A single variable holds one value. A collection holds many — and different collections organise those values in radically different ways. Choosing the right collection is like choosing the right tool from a toolbox: a screwdriver works for screws, but you would not use it to cut wood.

What you'll learn in this chapter

  • List<T> — the general-purpose, ordered, resizable collection
  • Dictionary<TKey,TValue> — fast key-value lookups like a contact book
  • HashSet<T> — enforces uniqueness, like a set of stamps
  • Queue<T> — first in, first out — like a bank queue
  • Stack<T> — last in, first out — like a stack of plates
  • When to use each type
🧰 The Toolbox Analogy

A carpenter's toolbox has many tools — a hammer, a saw, a screwdriver, a tape measure. Each tool is designed for a specific job. You could theoretically drive a screw with a hammer, but it would be ugly and slow.

C# collections are the same. List<T> is your all-purpose hammer. Dictionary is your measuring tape — fast, precise lookup. HashSet is your stamp collection holder — no duplicates, period. Queue keeps things in line (literally). Stack keeps track of history. Right tool, right job.

List<T> — The All-Purpose Collection

List<T> is the collection you will use most often. It is an ordered sequence of elements that can grow and shrink dynamically. You can add, remove, search, and sort it. Duplicates are allowed. Order is preserved (elements stay in the order you add them). 

using System.Collections.Generic;

List<string> fruits = new List<string>();
fruits.Add("Apple");
fruits.Add("Banana");
fruits.Add("Cherry");
fruits.Add("Apple");   // duplicates allowed

Console.WriteLine(fruits.Count);          // 4
Console.WriteLine(fruits[1]);              // Banana (0-indexed)
Console.WriteLine(fruits.Contains("Cherry")); // True

fruits.Remove("Banana");                  // removes first match
fruits.Sort();                             // alphabetical sort in-place

foreach (var fruit in fruits)
    Console.WriteLine(fruit);
// Apple
// Apple
// Cherry

Use List<T> when you need an ordered collection with random access (getting item by index), when duplicates are fine, and when the size changes frequently.

Dictionary<TKey,TValue> — The Contact Book

A Dictionary maps keys to values. Think of a contact book: you look up a person by name (the key) and get their phone number (the value). Lookups are extremely fast — O(1) on average — regardless of how many entries there are. 

Dictionary<string, int> population = new()
{
    { "London", 9_000_000 },
    { "Lagos",  14_800_000 },
    { "Tokyo",  13_900_000 }
};

// Add or update
population["Nairobi"] = 4_400_000;

// Safe lookup with TryGetValue
if (population.TryGetValue("Lagos", out int lag))
    Console.WriteLine($"Lagos population: {lag:N0}");

// Iterate over key-value pairs
foreach (var kvp in population)
    Console.WriteLine($"{kvp.Key}: {kvp.Value:N0}");

// Check key existence before accessing (avoids KeyNotFoundException)
if (population.ContainsKey("Cairo"))
    Console.WriteLine(population["Cairo"]);
else
    Console.WriteLine("Cairo not found");
💡 Always Use TryGetValue

If you access a dictionary with dict["key"] and the key doesn't exist, you get a KeyNotFoundException at runtime. The safe pattern is always TryGetValue(key, out var value) — it returns false instead of throwing if the key is missing. Only use the indexer when you are certain the key exists.

HashSet<T> — The Stamp Collection

A HashSet<T> stores unique items only. If you try to add a duplicate, it is silently ignored. This makes it perfect for tracking membership, deduplicating data, and set operations (union, intersection, difference). 

HashSet<string> tags = new() { "csharp", "dotnet", "backend" };

tags.Add("api");
tags.Add("csharp");   // already exists — silently ignored
Console.WriteLine(tags.Count);   // 4 (not 5)

// O(1) membership test — much faster than List.Contains
Console.WriteLine(tags.Contains("dotnet"));  // True

// Set operations
HashSet<int> setA = new() { 1, 2, 3, 4 };
HashSet<int> setB = new() { 3, 4, 5, 6 };

setA.IntersectWith(setB);   // setA is now { 3, 4 }
setA.UnionWith(setB);       // adds setB items not yet in setA
setA.ExceptWith(setB);      // removes items that are also in setB

// Deduplicate a list in one line
List<int> withDupes = new() { 1, 2, 2, 3, 3, 3 };
HashSet<int> unique = new(withDupes);   // { 1, 2, 3 }

Queue<T> — The Bank Line

A Queue<T> is a first-in, first-out (FIFO) collection. Imagine customers waiting at a bank: the first person to arrive is the first to be served. The queue is a natural model for task scheduling, message processing, and breadth-first graph traversal. 

Queue<string> customerQueue = new();

// Enqueue — add to the back of the line
customerQueue.Enqueue("Alice");
customerQueue.Enqueue("Bob");
customerQueue.Enqueue("Charlie");

Console.WriteLine($"People waiting: {customerQueue.Count}");  // 3

// Peek — see who is next without removing them
Console.WriteLine($"Next: {customerQueue.Peek()}");   // Alice

// Dequeue — serve the front customer (removes them)
string served = customerQueue.Dequeue();
Console.WriteLine($"Serving: {served}");            // Alice
Console.WriteLine($"Next now: {customerQueue.Peek()}"); // Bob

// Process the whole queue
while (customerQueue.Count > 0)
{
    string customer = customerQueue.Dequeue();
    Console.WriteLine($"Serving {customer}...");
}
// Serving Bob...
// Serving Charlie...

Stack<T> — The Plate Stack

A Stack<T> is last-in, first-out (LIFO). Imagine a stack of plates in a cafeteria: you always take from the top, and you always add to the top. Stacks are used for undo/redo systems, browser history, expression parsing, and recursive algorithm simulation. 

Stack<string> browserHistory = new();

// Push — navigate to pages (add to top of stack)
browserHistory.Push("google.com");
browserHistory.Push("github.com");
browserHistory.Push("stackoverflow.com");

Console.WriteLine($"Current page: {browserHistory.Peek()}");  // stackoverflow.com

// Pop — press "Back" (remove top)
string back = browserHistory.Pop();
Console.WriteLine($"Went back from: {back}");                 // stackoverflow.com
Console.WriteLine($"Now on: {browserHistory.Peek()}");         // github.com

// Check if stack is not empty before popping
if (browserHistory.TryPop(out string? page))
    Console.WriteLine($"Popped: {page}");   // github.com

Choosing the Right Collection

Here is a quick decision guide:

  • Need ordered items, duplicates OK, and index access? Use List<T>.
  • Need to look things up by a key? Use Dictionary<TKey,TValue>.
  • Need unique items only, or fast membership tests? Use HashSet<T>.
  • Need to process items in the order they arrived? Use Queue<T>.
  • Need to process the most recently added item first (undo, history)? Use Stack<T>.
Collection | Order | Duplicates | Fast Access | Use Case ------------------|-------------|------------|--------------|--------------------------- List<T> | Insertion | Yes | By index | General-purpose ordered list Dictionary<K,V> | Unordered | No (keys) | By key O(1) | Lookup tables, caching HashSet<T> | Unordered | No | Contains O(1)| Unique items, set operations Queue<T> | FIFO | Yes | Front only | Task queues, message buses Stack<T> | LIFO | Yes | Top only | Undo/redo, navigation history
🎯 Performance Notes

List<T>.Contains() is O(n) — it checks every element. For large lists where you need frequent membership tests, switch to a HashSet<T> which is O(1).

Dictionary and HashSet both use a hash table internally. They are O(1) for Add, Remove, and Contains on average — but O(n) in the worst case if you have many hash collisions. In practice, collisions are extremely rare.

For a sorted dictionary (keys in order), use SortedDictionary<TKey,TValue> — it's O(log n) instead of O(1) but always keeps keys sorted.

Collection Initialiser Syntax

C# lets you initialise any collection inline in a clean, readable way: 

// All of these use collection initialisers
List<int> numbers = [1, 2, 3, 4, 5];   // C# 12 collection expression

Dictionary<string, bool> flags = new()
{
    ["debug"]   = false,
    ["verbose"] = true,
    ["dryRun"]  = false
};

HashSet<string> allowedRoles = ["admin", "editor", "viewer"];
📚 Key Terms

List<T>: Ordered, indexed, resizable collection. Allows duplicates. Best for general-purpose ordered data.

Dictionary<TKey,TValue>: Key-value map with O(1) average lookup. Keys must be unique.

HashSet<T>: Unordered collection of unique items. O(1) for Add/Remove/Contains. Great for membership tests.

Queue<T>: FIFO collection. Enqueue adds to back; Dequeue removes from front.

Stack<T>: LIFO collection. Push adds to top; Pop removes from top.

IEnumerable<T>: The common interface all collections implement. LINQ works on anything that implements IEnumerable<T>.

Chapter Summary

  • List<T> is the default choice for ordered data — flexible, indexed, and allows duplicates.
  • Dictionary<TKey,TValue> gives O(1) key-based lookups; use TryGetValue for safe access.
  • HashSet<T> enforces uniqueness and is O(1) for membership tests — much faster than List.Contains for large sets.
  • Queue<T> is FIFO — use it for task processing in arrival order.
  • Stack<T> is LIFO — use it for undo history, depth-first traversal, and back-navigation.
  • All collections implement IEnumerable<T>, which means LINQ (Chapter 11) works on all of them uniformly.
