What to Learn Next

Finishing a book is a beginning, not an ending. You now have a solid foundation in C#, .NET, and ASP.NET Core. The question is: what do you build on top of it? This chapter gives you a realistic, structured roadmap for the next six months.

What this chapter covers

  • A "Next 30 Days" plan — what to build first to consolidate your learning
  • A "Next 3 Months" plan — deeper skills that will make you job-ready
  • A "Next 6 Months" plan — professional-level topics that set you apart
  • Recommended resources: courses, blogs, YouTube channels, and documentation
  • The right mindset for continued growth as a .NET developer

The Learning Roadmap

Before we dive into the roadmap, one piece of advice: learning by building beats learning by reading, always. Every topic in this roadmap will stick far better if you apply it in a project rather than just reading about it. Pick a project idea you care about and use it as the vehicle for learning each new skill.

A simple but effective project idea: a personal expense tracker with a REST API backend (users, expenses, categories), authentication, a basic frontend (or just curl), and deployed to Azure. This single project can absorb everything in this roadmap.

Next 30 Days — Consolidate and Build

The first 30 days are about making sure what you have learned in this book is truly solid. The best way to do that is to build something end-to-end.

🗓️ 30-Day Action Plan

Week 1–2: Build a Complete CRUD API.
Build a task management API from scratch: User registration and login (JWT), a Task resource (create, read, update, delete), Entity Framework Core with SQLite or SQL Server, Data Annotations or FluentValidation, global exception handling. Refer back to this book whenever you get stuck — that is what it is for.

Week 3: Add Tests.
Write unit tests for your service layer using xUnit. Learn to mock dependencies with Moq. Aim for 60%+ test coverage. Testing is the skill that separates junior developers from mid-level ones more than almost anything else.

Week 4: Deploy It.
Put your API on the internet. Azure App Service has a free tier. GitHub Actions can automate deployment. Having a live URL you can share with people is motivating and teaches you real-world concerns (environment variables, HTTPS, connection strings in production).

A Minimal xUnit Test to Get You Started

using Xunit;
using Moq;
using FluentAssertions;

public class UserServiceTests
{
    private readonly Mock<IUserRepository> _mockRepo;
    private readonly UserService _sut; // sut = System Under Test

    public UserServiceTests()
    {
        _mockRepo = new Mock<IUserRepository>();
        _sut = new UserService(_mockRepo.Object);
    }

    [Fact]
    public async Task GetUserById_WhenUserDoesNotExist_ThrowsNotFoundException()
    {
        // Arrange
        _mockRepo.Setup(r => r.GetByIdAsync(99)).ReturnsAsync((User?)null);

        // Act & Assert
        await _sut.Invoking(s => s.GetUserByIdAsync(99))
            .Should().ThrowAsync<NotFoundException>();
    }
}

Next 3 Months — Become Job-Ready

After you have a working, tested, deployed project, it is time to fill in the gaps that separate a self-taught developer from one who is ready for a professional environment.

Docker and Containerisation

Every modern development team uses Docker. Learn to write a Dockerfile for your ASP.NET Core API (we showed a template in Chapter 24). Learn docker-compose to run your API alongside a SQL Server or PostgreSQL container locally. Then deploy a container to Azure Container Apps or Azure Container Instances. 

# docker-compose.yml — run your API and database together
version: '3.8'
services:
  api:
    build: .
    ports:
      - "8080:8080"
    environment:
      - ConnectionStrings__Default=Server=db;Database=MyApp;User=sa;Password=YourPass123!
    depends_on:
      - db

  db:
    image: mcr.microsoft.com/mssql/server:2022-latest
    environment:
      SA_PASSWORD: "YourPass123!"
      ACCEPT_EULA: "Y"
    ports:
      - "1433:1433"

Async/Await Deeply

This book has used async/await throughout, but we have not gone deep. Understand these topics properly:

  • The difference between Task, Task<T>, and ValueTask<T>
  • What ConfigureAwait(false) does and when to use it
  • Task.WhenAll() and Task.WhenAny() for parallel async operations
  • CancellationToken — how to propagate cancellation through async call chains
  • How to avoid deadlocks in async code

Caching

Caching is one of the simplest ways to dramatically improve API performance. Learn both levels: 

// In-memory cache — fast, but per-instance (not shared across servers)
builder.Services.AddMemoryCache();

// In your service
if (!_cache.TryGetValue($"user:{userId}", out UserDto? user))
{
    user = await _repo.GetUserAsync(userId);
    _cache.Set($"user:{userId}", user, TimeSpan.FromMinutes(5));
}

// Distributed cache (Redis) — shared across multiple server instances
builder.Services.AddStackExchangeRedisCache(options =>
    options.Configuration = builder.Configuration["Redis:ConnectionString"]);

Message Queues in Practice

Chapter 24 introduced the concept of message queues. Now implement one. MassTransit with RabbitMQ is the recommended starting point — great documentation and abstracts the broker-specific code beautifully. 

dotnet add package MassTransit.RabbitMQ

Next 6 Months — Professional-Level Skills

At six months, you should be thinking about the skills that senior developers are expected to have. These take time — they reward patient, deliberate learning.

Integration Testing

Unit tests test individual classes in isolation. Integration tests test your actual HTTP endpoints against a real (test) database. ASP.NET Core provides WebApplicationFactory<T> for this: 

public class UsersControllerTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient _client;

    public UsersControllerTests(WebApplicationFactory<Program> factory)
        => _client = factory.CreateClient();

    [Fact]
    public async Task GetUser_ReturnsOk_WhenUserExists()
    {
        var response = await _client.GetAsync("/api/users/1");
        response.StatusCode.Should().Be(HttpStatusCode.OK);
    }
}

gRPC for Service-to-Service Communication

REST over HTTP/JSON is the most common protocol for service communication, but it is not the most efficient. gRPC uses Protocol Buffers (binary serialisation) and HTTP/2, giving much higher throughput and lower latency for internal service-to-service calls. ASP.NET Core has excellent gRPC support via the Grpc.AspNetCore package.

OpenTelemetry and Observability

In production, you need to understand what your application is doing. Learn the three pillars of observability:

  • Logs — structured logging with Serilog, outputting to Azure Monitor or Seq.
  • Metrics — counters and gauges (request rate, error rate, latency) exported to Prometheus or Azure Monitor.
  • Traces — distributed request tracing with OpenTelemetry and Jaeger.
dotnet add package OpenTelemetry.Extensions.Hosting
dotnet add package OpenTelemetry.Instrumentation.AspNetCore
dotnet add package OpenTelemetry.Exporter.Console

Domain-Driven Design (DDD) Concepts

As your applications grow, how you structure and name things becomes as important as how you code them. Domain-Driven Design gives you a vocabulary and set of patterns for modelling complex business domains: Aggregates, Value Objects, Repositories, Domain Events, and Bounded Contexts. Read "Domain-Driven Design Distilled" by Vaughn Vernon as a practical starting point.

The Right Mindset

One final piece of advice. The developers who progress fastest are not the ones who read the most — they are the ones who ship the most. Build things. Break things. Read error messages carefully. Search for answers. Fix bugs. Ship again.

Imposter syndrome is real in this industry. You will feel like everyone else knows more than you. They don't — they just have a different set of gaps. Every senior developer has things they quietly don't understand. The difference is that experienced developers have learned to be comfortable with not knowing and confident in their ability to figure things out.

Build something. Put it on GitHub. Show it to people. Apply for jobs even before you feel ready. The gap between "ready" and "actually ready" is smaller than you think.

Chapter Summary — Your Roadmap

  • Next 30 days: Build a complete CRUD API, add xUnit tests with Moq, deploy to Azure App Service.
  • Next 3 months: Learn Docker and docker-compose, deepen async/await knowledge, add caching (IMemoryCache then Redis), implement a message queue with MassTransit.
  • Next 6 months: Write integration tests with WebApplicationFactory, learn gRPC, set up OpenTelemetry for observability, study Domain-Driven Design.
  • Ongoing resources: Microsoft Learn, Andrew Lock's blog, Nick Chapsas on YouTube, C# in Depth by Jon Skeet.
  • The rule: Build things. Ship things. Learning accelerates dramatically when you are solving real problems.
