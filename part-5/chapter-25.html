The .NET Ecosystem

ASP.NET Core is only one corner of the .NET world. The ecosystem extends into mobile and desktop apps, browser-based applications written in C#, machine learning, real-time communications, and one of the richest cloud platforms in the world. Let's take a tour.

What you'll learn in this chapter

  • .NET MAUI — one codebase for iOS, Android, Windows, and macOS
  • Blazor — C# running in the browser via WebAssembly
  • ML.NET — machine learning in C# without Python
  • SignalR — real-time communications ("the WhatsApp of .NET")
  • Azure as the natural cloud home for .NET applications
  • NuGet — the .NET package manager
  • Visual Studio vs VS Code vs Rider — choosing your IDE
  • The open-source story and the .NET Foundation
  • .NET release cadence — LTS vs Standard Term Support

The .NET Landscape — Beyond ASP.NET Core

When most beginners think of .NET, they think of web APIs. And while ASP.NET Core is absolutely the flagship framework for backend development, the .NET platform has grown into something far wider. In 2024, C# developers write mobile apps, desktop applications, browser UIs, real-time chat systems, and machine learning models — all in the same language they use for their APIs.

This chapter is a landscape overview. We won't go deep into any one technology — each could fill its own book. But by the end, you'll have a map of the territory, and you'll know where to go when you want to build something that isn't a REST API.

.NET MAUI — One Codebase, Every Platform

.NET MAUI (Multi-platform App UI) is Microsoft's framework for building native mobile and desktop applications in C# and XAML. A single codebase compiles and runs natively on iOS, Android, Windows, and macOS.

  • Share 90%+ of your code across platforms
  • Access native device APIs (camera, GPS, sensors) via the MAUI Essentials library
  • Renders native controls on each platform — not a web view, not a simulation
  • The successor to Xamarin.Forms (which MAUI replaces)
// A simple MAUI page — notice it's just C# classes
public class MainPage : ContentPage
{
    private int _count = 0;

    public MainPage()
    {
        var button = new Button { Text = "Click me" };
        button.Clicked += (s, e) =>
        {
            _count++;
            button.Text = $"Clicked {_count} times";
        };

        Content = new VerticalStackLayout
        {
            new Label { Text = "Hello, MAUI!", FontSize = 24 },
            button
        };
    }
}
📱 MAUI vs React Native vs Flutter

The cross-platform mobile space has several competitors. React Native (JavaScript), Flutter (Dart), and MAUI (.NET) all let you write one codebase for iOS and Android. If you are already a C# developer building backends in .NET, MAUI is the natural extension — you can share models, DTOs, and business logic between your API and your mobile app.

Blazor — C# in the Browser

Blazor is perhaps the most technically remarkable thing in the modern .NET ecosystem: it lets you write interactive browser UIs in C# instead of JavaScript. It comes in two flavours:

Blazor WebAssembly

The .NET runtime is compiled to WebAssembly and shipped to the browser. Your C# code runs client-side, inside the browser itself — no server round-trip for UI interactions. This is a genuine C# SPA (Single Page Application) framework.

Blazor Server

The component logic runs on the server, and UI changes are communicated to the browser via SignalR (a persistent WebSocket connection). Lower initial load, but requires a constant server connection.

Here is a complete Blazor component — notice it is C#, not JavaScript:

@* Counter.razor — a Blazor component *@
@page "/counter"

<h1>Counter</h1>

<p>Current count: <strong>@currentCount</strong></p>

<button class="btn btn-primary" @onclick="Increment">Click me</button>

@code {
    private int currentCount = 0;

    private void Increment()
    {
        currentCount++;
    }
}

The @code { } block is real C#. The @onclick event handler calls a C# method. There is no JavaScript in sight. Blazor handles the DOM updates automatically.

💡 Who is Blazor For?

Blazor is ideal for C# teams who want to build interactive web UIs without learning a JavaScript framework. It is popular in enterprise environments where teams are already deep in .NET and want to avoid context-switching to React or Angular. It is not a replacement for React/Vue/Angular in all scenarios — those ecosystems are larger and have more tooling — but for C#-first teams it is a compelling option.

SignalR — Real-Time Communications

SignalR is ASP.NET Core's library for real-time, bidirectional communication between server and clients. Think of it as the "WhatsApp of .NET" — it is how you build features where the server needs to push data to the browser without the browser having to ask.

SignalR uses WebSockets when available, falling back to long-polling for older clients. It supports:

  • Live chat applications
  • Real-time dashboards and analytics
  • Collaborative editing (like Google Docs)
  • Live notifications ("You have a new message")
  • Multiplayer games
  • Live sports score updates
// A simple SignalR Hub — the server-side hub for a chat app
public class ChatHub : Hub
{
    public async Task SendMessage(string user, string message)
    {
        // Broadcast the message to ALL connected clients
        await Clients.All.SendAsync("ReceiveMessage", user, message);
    }

    public async Task JoinGroup(string groupName)
    {
        await Groups.AddToGroupAsync(Context.ConnectionId, groupName);
        await Clients.Group(groupName).SendAsync("UserJoined", Context.ConnectionId);
    }
}

ML.NET — Machine Learning in C#

ML.NET is Microsoft's machine learning framework for .NET developers. It brings ML capabilities to C# without requiring Python or TensorFlow knowledge, though it can interoperate with ONNX models from PyTorch and TensorFlow.

ML.NET supports:

  • Binary and multiclass classification
  • Regression (predicting values like house prices)
  • Clustering (grouping similar items)
  • Anomaly detection
  • Natural language processing (text classification, sentiment analysis)
  • Image classification (via deep learning models)
  • Recommendation systems

ML.NET Model Builder in Visual Studio provides a drag-and-drop UI to train models locally or on Azure, then generates C# code to integrate the model into your application.

Azure — The Natural Cloud for .NET

Microsoft Azure is the cloud platform most naturally aligned with the .NET ecosystem. Every .NET service has deep Azure integration, and the Azure SDK for .NET is first-class. Key Azure services that .NET developers use most:

  • Azure App Service — deploy ASP.NET Core APIs and web apps with a single git push or GitHub Actions pipeline.
  • Azure Functions — serverless compute for event-driven C# code (HTTP triggers, timer triggers, message queue consumers).
  • Azure SQL Database — managed SQL Server in the cloud. Works identically with Entity Framework Core.
  • Azure Cosmos DB — globally distributed NoSQL database with a .NET SDK.
  • Azure Key Vault — secure storage for secrets, certificates, and API keys. Deep integration with ASP.NET Core configuration.
  • Azure Service Bus — enterprise message queue for microservices.
  • Azure Active Directory (Entra ID) — identity platform, integrates with ASP.NET Core authentication.

NuGet — The .NET Package Manager

NuGet is to .NET what npm is to Node.js. Every third-party library you have used in this book — FluentValidation, Entity Framework Core, Polly, Serilog, AutoMapper — lives on nuget.org and is installed with a single command: 

dotnet add package PackageName
dotnet add package PackageName --version 13.0.1

As of 2024, nuget.org hosts over 350,000 packages. The .NET package ecosystem has reached maturity — there is a well-maintained library for almost everything.

IDE Choices — Visual Studio vs VS Code vs Rider

.NET developers have three excellent choices for their development environment:

  • Visual Studio 2022 (Windows only, free Community edition): The original, most feature-rich IDE for .NET. Exceptional debugger, integrated profiler, database explorer, Azure deployment tools, and MAUI designer. The go-to for Windows enterprise development.
  • Visual Studio Code (Windows/Mac/Linux, free): A lightweight, fast editor with excellent C# support via the C# Dev Kit extension. Great for cross-platform development, ASP.NET Core, and developers who prefer keyboard-driven workflows.
  • JetBrains Rider (Windows/Mac/Linux, paid): A full-featured cross-platform IDE from JetBrains. Many developers consider it to have the best C# intelligence and refactoring tools of any IDE. Popular in teams that also use IntelliJ IDEA for Java.
💡 Which IDE Should You Start With?

If you are on Windows and money is not a concern, start with Visual Studio Community 2022 — it is free and the most beginner-friendly. If you are on Mac or Linux, use VS Code with the C# Dev Kit. If you are a professional developer who wants the best tooling available across platforms and is happy to pay for a licence, Rider is worth every penny.

The Open-Source Story

In 2016, Microsoft did something that would have been unthinkable a decade earlier: they open-sourced .NET Core (the modern, cross-platform .NET) and moved development to GitHub. All of ASP.NET Core, the C# compiler (Roslyn), Entity Framework Core, and the entire .NET runtime are now open source under permissive licences.

This was a transformational moment. The .NET community exploded. Contributions from outside Microsoft accelerated the platform. Performance improvements that made .NET one of the fastest web frameworks in the world came partly from community contributors.

📊 The .NET Foundation

The .NET Foundation is an independent non-profit organisation that stewards open-source .NET projects. It supports projects like Blazor, SignalR, MAUI, NUnit, and dozens of others — providing legal, financial, and governance support. The foundation ensures that even if Microsoft's priorities changed, the community could continue developing the ecosystem. Members include Microsoft, Google, Red Hat, and hundreds of individual contributors.

.NET Release Cadence — LTS vs STS

Microsoft releases a new version of .NET every November. Odd-numbered versions are Standard Term Support (STS, 18 months); even-numbered versions are Long-Term Support (LTS, 3 years):

  • .NET 6 (LTS) — supported until November 2024
  • .NET 7 (STS) — reached end of life May 2024
  • .NET 8 (LTS) — supported until November 2026 — use this for production
  • .NET 9 (STS) — released November 2024, supported until May 2026
  • .NET 10 (LTS) — due November 2025, will be supported until November 2028

The rule of thumb: run LTS versions in production. They have longer support windows, fewer breaking changes, and are what most libraries and frameworks are tested against.

Chapter Summary

  • .NET MAUI enables cross-platform native mobile and desktop apps (iOS, Android, Windows, macOS) from a single C# codebase.
  • Blazor brings C# to the browser — write interactive UIs without JavaScript, using either WebAssembly (client-side) or Server (server-side via SignalR).
  • SignalR provides real-time, bidirectional communication between server and clients — ideal for chat, live notifications, dashboards, and collaboration features.
  • ML.NET brings machine learning to the .NET ecosystem: classification, regression, NLP, and more — without leaving C#.
  • Azure is the natural cloud home for .NET: App Service, Functions, SQL Database, Key Vault, Service Bus, and Cosmos DB all have first-class .NET support.
  • NuGet is the .NET package manager with 350,000+ packages. Install with dotnet add package.
  • Choose Visual Studio 2022 (Windows), VS Code (cross-platform), or Rider (cross-platform, paid) for your IDE.
  • .NET was open-sourced in 2016; use LTS versions (.NET 8, .NET 10) in production.
